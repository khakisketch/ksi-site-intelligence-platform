## 3. 다음 개발 — M3 나머지 (2~6단계) ★본체

M3 = **"만들었지만 쓸 수 없는 것"을 쓸 수 있게 만드는 트랙**. 1단계(프로덕션 조립)만 닫혔다.
아래 5개는 goal-ledger에 **미등록** — 착수 전 각각 `register --kind product` 한다.

### 3-1. 사진 업로드 · 재구성 발행 UI (최우선)
지금 사용자는 핵심 가치(반복비행→체적/변화 리포트)를 **UI로 실행할 수 없다**.
백엔드는 이미 있다 — `POST /v1/missions/{mission_id}/source-media`,
`POST /v1/processing-jobs`, `GET /v1/processing-jobs/{job_id}`.
CLI 참조 구현: `tools/upload_source_bundle.py`.

- 대상: `apps/dashboard/src/app/missions/[missionId]/` 아래 신규 섹션
- 필요: 다중 파일 선택 → presigned PUT 병렬 업로드 → 진행률 → 번들 봉인 →
  processing-job 발행 → 상태 폴링 → 완료 시 `/reports` 링크
- 수용기준: 실 Core + 실 MinIO 로 사진 N장을 **브라우저에서만** 올려 재구성 완주,
  `/reports` 에서 결과 확인(390/768/1440 렌더 확인)
- 기존 재사용: `OrthophotoOverlay`, `apps/dashboard/src/app/reports/page.tsx` 의 조회 패턴

### 3-2. 커버리지 보고 장비-임무 대조 (INV-010 무결성 공백)
`services/core/src/ksi_core/coverage_reports.py` 가 제출 장비와 임무 배정 장비를 대조하지 않는다.
- 수용기준: 임무에 배정되지 않은 device_id 의 CoverageReport 제출이 typed 거부되고,
  그 거부가 원장에 남는다(기존 "거부된 완료 주장 조회 표면" 경로 재사용 — 커밋 `01fea90`)

### 3-3. 관측성 — 구조화 로깅 + 기본 메트릭
현재 `logging.getLogger` 산발. 프로덕션 진단 불가.
- 수용기준: 요청/작업 단위 correlation id 가 로그에 관통, `/metrics` 또는 동등 표면에
  요청 수·지연·처리작업 상태 카운터 노출, docker 종단 기동에서 실측

### 3-4. 실사용자 인증 — 토큰 만료 · 회전
현재 `KSI_CORE_PRINCIPAL_TOKENS_JSON` 의 sha256 digest 정적 목록뿐 — 만료도 회전도 없다.
- 수용기준: 만료된 토큰 401, 회전 중 겹침 구간 동시 유효, 회전 절차 문서화.
  서명키 회전 절차(커밋 `d2b0402`)와 같은 모양을 따른다.
- **위험 표면(인증) → goal verification 은 strict 로 자동 승격된다. reviewer 반증 필수.**

### 3-5. retention 스케줄러 연결
`services/core/src/ksi_core/retention.py` 는 집행 엔진만 있고 **호출자가 없다**(`main`/스케줄러 부재).
- 수용기준: 주기 실행 진입점 + tombstone-먼저 순서 보존 확인 + 컨테이너에서 실동작
- **미해소 리스크 `retention-defaults-legal`**: 보관기간 기본값(候補30·확정1095일)의 법적
  적정성이 미검토다. 코드 작업과 별개로 **대표자 판단 필요** — 기본값을 바꾸는 결정은 하지 않는다.
