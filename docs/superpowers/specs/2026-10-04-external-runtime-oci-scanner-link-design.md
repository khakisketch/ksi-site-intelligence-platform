## Purpose and proven need

The Human selected a verified OCI archive link instead of treating different IDs as equal.
The goal is to bind an unchanged native Grype report to the actual host-observed runtime image
on the existing Linux ARM64 Docker29 containerd store. Keep the original report, actual Docker
ID and release reference intact; prove their relation rather than fabricate a compatible record.

The completed narrow consumer retains strict equality, so real Docker index IDs correctly
fail against Grype config IDs. Explicit platform inspection yields the platform manifest,
not the config. Both new runtime archives prove the complete distinct chain; see
[actual verification](../../ops/SPATIAL_DATA_LOCAL_VERIFICATION.md#python-repair-and-native-scanner-consumer--2026-10-04).
The archive is existing trusted-build output, not a customer reconstruction input. It is read
only as evidence; no image, TAR member, raster parser or vendor application is executed.

## Contract versions and exact responsibility

Keep canonical `release-evidence.v1` unchanged. Add separate
`contracts/schemas/external-runtime-host-binding.v2.json`; do not silently extend v1.
The stage accepts v1 or v2 explicitly. V1 shape and behavior remain unchanged, including
direct scanner/config equality and its blocking result when the host ID is an index.
Unknown versions/fields and mixed partial versions fail closed.

V2 has the same source/release/product/dependency structure as v1 except:
- `schemaVersion` is exactly `external-runtime-host-binding.v2`.
- Each of the two `runtimeProducts` additionally requires `ociArchive`.
- `ociArchive` has exactly `path`, `sha256`, `bytes`, `type`; `type` is `oci-archive`.
  Path is absolute without `..`; SHA256 is lowercase `sha256:` plus64hex; bytes is a positive
  integer no greater than1GiB. Root and other nested records remain strict, no extra fields.
- `dockerImageId` remains the genuinely observed Docker ID (OCI index on this store).
  It is **not** replaced by a scan config ID. Core/Dashboard and external dependency records
  remain unchanged and must pass their existing verification paths.

Do not add operator-declared `configDigest`/`manifestDigest` as trusted expected IDs. The
verifier derives them from raw content addressed by the independently host-verified index.
No wrapper scanner envelope, manual report field, digest alias, auto-issued host observation,
registry promotion, signature, waiver, trust input or credential is generated by this design.

## Read-only OCI link verifier

Add focused stdlib tool `tools/verify_external_oci_archive.py`. It consumes:

```text
absolute archive path + expected archive SHA256/length
expected host OCI index digest + exact clean source commit + runtime role
```

The role is exactly `inspector` or `measurement`; source is40lowercasehex. Invalid expected
bindings are rejected before use. This supported v2 profile is Linux ARM64; other stores or
platforms require an explicitly reviewed profile, not implicit fallback or architecture guessing.

Safe file handling:
- Traverse normalized absolute parent/leaf with descriptor-relative `O_NOFOLLOW`, open once,
  require nonempty regular file at most1GiB; reject symlinks, special files and unsupported paths.
- Hash the full raw archive, compare expected length/hash and stable descriptor/directory-entry
  identity before/after all verification. Seek/parse the same protected descriptor, not a second
  pathname open. Any observed change/replacement, short read or hash mismatch is a blocker.
- Accept only uncompressed outer TAR with at most4096members. Never extract. Walk checked512byte
  raw headers before reading member data; allow only regular-file and directory type flags.
  Reject PAX/GNU long-name/sparse/other extension flags **before** an advanced TAR parser can
  allocate extension payloads. Checked member size/offset/padding must stay within bound archive
  bytes; require two zero end blocks and only zero trailing padding. Both actual archives have
  26members, only regular/directory flags, no extensions. Reject duplicate
  normalized names, absolute/traversing names, link/special members and oversized metadata.
  Directory markers are permitted; a zero-sized marker is not an evidence blob.
- `index.json`, `oci-layout` and each JSON index/manifest/config is at most1MiB. Strict UTF-8
  JSON rejects duplicate keys, non-finite values, malformed/deep invalid trees and wrong roots.
  TAR/JSON/read errors expose safe reason codes, not embedded configuration or other contents.
- Layer payloads are hashed as raw bytes, never decompressed, decoded or extracted.
- Supported members are regular `index.json`, `oci-layout`, optional Docker compatibility
  `manifest.json` (not an identity authority), and `blobs/sha256/<64hex>`, plus their directory
  markers. Reject other paths; do not interpret a Docker synthetic manifest as an OCI identity.

Cryptographic verification:
1. Require OCI layout1.0.0, root index schemaVersion2, exactly one image-root descriptor matching
   the supplied host index. Supported media type is OCI image index; reject an unlinked image.
2. Require its raw `blobs/sha256/<digest>` regular-file bytes to match descriptor size and digest.
   Parse that **verified** nested index. Require exactly one Linux ARM64 image manifest; accepted
   variant is absent or `v8`. Unknown/nonmatching platforms/attestations are not candidates.
3. Follow and verify the selected manifest's raw size/digest/media type (OCI image manifest),
   then its config size/digest/media type. Require schemaVersion2, bounded layer descriptors,
   lowercase SHA256 references and exact blob sizes; no missing/duplicate descriptor ambiguity.
4. Verify every archived content-addressed blob's actual name/hash and every referenced blob
   required by the index graph, including attestation artifacts. Layer blobs are streamed raw.
   Foreign/external blob URLs and unrecognized graph media types fail closed. No network reads.
   Supported image layer media types are `application/vnd.oci.image.layer.v1.tar`, that type
   with `+gzip` or `+zstd`; only OCI config/index/manifest metadata types above are accepted.
   Non-executable attestation manifests may use `application/vnd.in-toto+json` layer blobs
   and `unknown/unknown` platform as observed in both actual archives; verify their bytes,
   but never select them as the ARM64 runtime or treat their contents as a verified signature.
    Bound index manifests and manifest layers to64entries each and graph depth to8; referenced
    shared content blobs are permitted, duplicate conflicting descriptors are not.
    Reuse completed verification by digest, retaining the verified subtree height (not only
    a visited bit). Every reused path must still satisfy `depth + height - 1 <= 8`. Validate
    every incoming descriptor before reuse so conflicting size/media/URLs cannot hide in cache.
    The total descriptor-check budget is270337, derived from1root-binding check plus
    4096members×(64layers+1config+1optional subject). This is an explicit whole-traversal
    ceiling, not a larger per-node allowance. Exhaustion fails `OCI_WORK_LIMIT` before further
    traversal. Metadata is expanded once per verified digest; cache space is bounded by the
    existing member cap and stores only height/identity, never whole layer bytes.
5. Require actual config `os=linux`, `architecture=arm64`,
   `config.Labels["org.opencontainers.image.revision"] == supplied clean source commit`,
   and the existing exact role-specific `User`/single fixed `Cmd`:
   inspector `ksi-inspector-image` / `/app/.venv/bin/ksi-external-inspector-entrypoint`;
   measurement `ksi-measurement-image` / `/app/.venv/bin/ksi-external-measurement-entrypoint`.
   Verify config rootfs diff-ID/layer-count structure, but do not claim executable/runtime safety
   from metadata or invent UID/namespace/containment evidence.
6. Return the derived config SHA256 only after the entire archive and identity checks pass.
   It must never be copied from scanner JSON, caller-controlled fallback or a default image ID.

The existing independently verified host image ID/RepoDigests remain the trust anchor. Archive
hashes and OCI chains prove byte relation, not a truthful scanner producer, authenticated tool,
security disposition or registry publication. Their external review remains required.

## Stage and scanner integration

For each runtime role the stage first verifies its actual image/RepoDigests as today, then
checks the unchanged SBOM artifact. For v2 only, invoke the OCI verifier with this runtime's
`ociArchive`, actual host `dockerImageId`, role and canonical clean `source.gitCommitSha`.
Feed its successfully derived config ID to the existing strict scanner verifier along with
the scanner's original path/bytes/hash. Do not accept partial output or stale derived values
after a verifier failure; one role's derived ID never becomes the other's expected ID.

The native scanner additionally requires its own `source.target.os=linux` and
`source.target.architecture=arm64` for this v2 profile. Keep original findings and ignored
arrays intact. V1 and legacy compatibility do not acquire a fabricated native-image proof.
Use an explicit optional `require_linux_arm64=False` verifier argument and CLI flag
`--require-linux-arm64`; only v2 passes true after successful archive derivation. No default
platform or unsupported native version is inferred for v1 inputs.
Legacy scanner envelopes can retain v2's independently verified archive provenance, but their
in-report truth/image link is still the pre-existing external review responsibility.

All existing clean-source, canonical/host artifact metadata, role/reference, protected ownership,
registry/RepoDigest, application bundle, signed execution/revocation/current Core and live socket
checks stay in place. Failure is `BLOCKED_RELEASE_EVIDENCE`; success validates only this evidence
link, not eligibility, activation or release approval. No service, Docker image build/load/export,
remote registry, scanner tool or installation is invoked by this verifier/consumer.

## Acceptance and negative evidence

Tracked tests use small clearly labeled synthetic OCI graphs, not release evidence. They require
both v1 legacy/native compatibility and v2 successful index→manifest→config→raw scanner linkage.
Mutations must reject wrong archive hash/length/index/source/role/platform/config, missing or
changed blob, incorrect descriptor size/media, duplicate TAR/JSON names, cycles/depth overflow,
foreign URLs, symlink/special/traversing paths, observed file change, malformed/oversized payload
and mixed/unknown wire versions. Wrong native config/platform and role swaps still block.
Oversized PAX/GNU extension headers must reject without reading/allocating their advertised body;
tests must cover truncated member/end blocks and nonzero trailing garbage as well.

Shell integration must prove v2 gets its ID from the verified archive, not report data, and still
rejects changed host image/RepoDigests, source/release hash or scanner bytes. Test stubs do not
establish real Docker, registry or service authority. No new Docker/archive producer is simulated
as genuine evidence.

Actual local verification uses both retained16084bf archives, their unchanged raw Grype reports
and independently observed index IDs; exactsource16084bf is used only for that standalone
historical-image check. Demonstrate both links plus wrong role/index/config/hash failures and
preserve original bytes. Those image config labels do not equal later HEAD and must never be
relabeled as a current-source full release. A later candidate needs genuine clean-current-source
builds/evidence and missing Core/Dashboard/registry/signing inputs; this task creates none of them.

Completion evidence includes source tests RED→GREEN, scoped and full regressions with actual
environment/revision, one independent read-only review, genuine historical archive/raw-report
