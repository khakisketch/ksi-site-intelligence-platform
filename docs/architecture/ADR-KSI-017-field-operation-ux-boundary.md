# ADR-KSI-017 — 현장 운용 UX 경계: MSDK 앱을 만들지 않는다

- 상태: PARTIALLY SUPERSEDED (2026-08-21, ADR-KSI-024)
- 관련: ADR-KSI-004(DJI 연동 이원화, 갱신), ADR-KSI-005(연결 아키텍처, 갱신),
  ADR-KSI-007(임무 이원 산출물), CLAUDE.md Control boundaries

## 맥락

> **후속 결정:** 이 문서의 “Pilot 2 웹뷰·RC 브라우저에서 KSI 화면 사용” 결정은
> ADR-KSI-024가 대체했다. 현재 정상 UX는 현장 노트북·컴퓨터의 하나의 반응형
> KSI Operations Console이다. Pilot 2 비행 전용, MSDK 비행 앱 금지, 비행 중
> KSI 판정 UI 금지와 조건부 preflight/postflight Bridge 경계는 계속 유효하다.

현장에서 조종기(RC Plus 2)를 쥔 사람이 KSI 시스템과 상호작용할 방법이 필요하다.
후보로 DJI Mobile SDK(MSDK) 기반 전용 앱을 검토했으나, 다음 이유로 채택하지
않는다.

## 결정

1. **MSDK 전용 앱을 만들지 않는다.** DJI Pilot 2를 그대로 쓰고, 그 안에서(웹뷰
   또는 조종기 브라우저로) 우리 화면을 연다. 근거: 비행 중 조종사의 손과 눈은
   조종기 화면에 묶여 있다 — 별도 앱은 화면 전환을 강요하고, 그 전환 자체가
   비행 중 위험 요소다. 대표자 확인: 조종기 브라우저로 대시보드 접속 가능,
   Pilot 2에 서드파티 클라우드/웹뷰 연결 메뉴 존재.
2. **비행 중에는 아무것도 새로 보여주지 않는다.** 대표자 확인: 비행 중 조종사가
   봐야/해야 하는 것은 DJI 기본 화면뿐이다. 그래서 v1 현장 화면은 **이륙
   전**(오늘 임무 확인·경로 확보)과 **착륙 후**(비행 결과·재관측 필요 여부)만
   다룬다.
3. **판정 로직을 화면/위젯에 넣지 않는다.** 위젯이든 조종기 화면이든 Manifold이
   이미 내린 결론을 표시하고 사람의 선택(재관측/승인/중단)만 되돌려 보낸다.
   같은 규칙이 서버·Manifold·조종기 세 곳에 따로 구현되면 반드시 갈라진다
   ("두 번째 진실" 방지) — 오늘 발견한 CRITICAL 확정 게이트·계약 rollback 문제가
   정확히 이 패턴(같은 판정이 여러 곳에 흩어져 한쪽만 고쳐짐)이었다.
4. **경로 전달 방식은 화면과 분리한다.** v1은 대시보드에서 파일을 내려받아 DJI
   앱으로 불러오는 수동 방식, 이후 Cloud API(ADR-KSI-004 갱신 참조)가 검증되면
   자동 배포로 교체한다. 화면은 "경로를 확보한다"만 알고 "어떻게"는 모른다 —
   교체 시 화면을 다시 만들지 않는다.

## 3계층 원칙 (실시간 업링크 관련, 이번 논의로 확정)

이번 논의에서 "비행 중 매니폴드 데이터를 지상으로 빼려면 기체 셀룰러 동글
아니면 MSDK 둘 중 하나가 필수"라는 초기 판단이 **틀렸음이 확인됐다** — PSDK에
Manifold 3 전용 `DjiCloudApi_SendDataByWebSocket()`이 있어 매니폴드→기체 링크
→Pilot 2→서버 실시간 업링크가 MSDK 없이 가능하다(단, M4D의 실제 지원 여부는
ADR-KSI-004 갱신에 남긴 미확인 항목). 이에 따라 책임을 3계층으로 분리한다:

| 계층 | 책임 | MSDK 필요 여부 |
|---|---|---|
| **온보드 루프** | Manifold의 인지·판단·재관측 결정. 지상망 장애와 무관하게 동작 | 아니오 |
| **실시간 업링크** | Manifold 상태·결과를 Pilot Cloud WebSocket으로 서버에 전송 | 아니오 |
| **하향 명령** | 서버→Manifold 명령(양방향 폐루프) | 실기로 M4D 지원 확인 전까지 보류 — 필요해지면 이때 MSDK+MOP 재검토 |

## 결과

- `apps/dashboard`에 현장 전용 라우트를 추가한다(별도 안드로이드 앱 아님).
  기존 임무·커버리지·시각표기 유틸을 재사용한다 — 신규 서버 API는 원칙적으로
  만들지 않는다.
- MSDK 도입은 폐기가 아니라 **보류**다. 재개 조건: 하향 명령(서버→매니폴드)이
  실제 제품 요구사항이 되고, M4D + Manifold 3 조합에서 Cloud MOP 양방향 경로가
  실기로 확인되지 않을 때.
- 이 경계를 벗어나는 제안(조종기 전용 앱, 화면에 판정 로직 추가, 위젯이 계약
  검증을 대신함)은 본 ADR 갱신 없이는 채택하지 않는다.
