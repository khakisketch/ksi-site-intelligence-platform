# ADR-KSI-018 — Phase 3 재정의: 자율 현장 수집이 중심축, 폐루프 완주가 최우선

- 상태: ACCEPTED (2026-08-14, 대표자 확정)
- 관련: MASTER_PRD §25(Phase 정의 — 본 ADR이 §25의 Phase 3 정의를 개정),
  ADR-KSI-016(제품 범위), ADR-KSI-017(현장 운용 UX 경계),
  `00_SYSTEM_OVERVIEW.md`, 목표 원장 `autonomous-acquisition-closed-loop`

## 맥락

2026-08-14 전수 실사에서 두 사실이 드러났다.

1. 완료 41건 중 **실제 비행에서 종단 검증(Field Proven)된 것이 0**이다. "경로
   생성·재구성·재관측 신호"가 각각 존재하지만, 실제 기체 기준 하나의 폐루프로
   이어진 증거가 없다.
2. PRD §25의 Phase 3("동적 장비 위험 인지" 중심)은 안전관리 방향이 지나치게
   강해, 이대로 두면 로드맵이 다시 "안전 AI → 공간정보" 순서로 끌려간다 —
   제품의 중심은 자율 현장 수집·공간정보다.

## 결정

1. **Phase 3의 중심축을 재정의한다: "자율 현장 수집(Autonomous Acquisition /
   Edge Intelligence)".** 내용: 임무 수신 → 실제 비행 실행 → 카메라·RTK·자세
   수집 → 관측 품질 판단 → 누락 영역 판단 → 재관측 지점 결정 → 통신두절 시
   로컬 지속 → 서버 동기화.
2. **기존 Phase 3의 "중장비 위험 자동 인지"는 Safety Trigger로 분리한다** —
   폐기가 아니라 위치 이동이다. 이미 완성된 위험 계산 로직(CPA/TTC·RiskField)은
   자율 수집 위에 얹히는 안전 신호 계층이 된다.
3. **최우선 목표는 기능 추가가 아니라 폐루프 1회 완주다.** 목표 원장
   `autonomous-acquisition-closed-loop`(strict, 완료기준 7개, HIL 증거 필수·
   자기보고 불인정)가 그 정의다:
   임무 발급 → Manifold 수신·검증 → 실제 M4D 수행 → 사진/위치/자세 수집 →
   dataset 자동 봉인 → 서버 ingest → reconstruction → 변화/진척 분석 →
   재관측 필요 판정 → 새 임무.
4. **실행 우선순위 P0~P3:**
   - P0 — 실제 Manifold 3 HIL: DPK 설치 → 기동 → PSDK 실제 데이터 수신 →
     임무 수신·검증
   - P1 — 실제 수집 종단: M4D 촬영 → 자동 ingest → reconstruction까지 사람의
     수동 사진 업로드 없이 연결
   - P2 — 분석→재관측 폐루프: 변화영역/관측부족 → 재관측 위치 → 임무 생성 →
     Manifold 수행
   - P3 — 최소 사용자 UI: 지도 하나에서 `지난 현장 → 현재 현장 → 변화영역 →
     재확인 영역 → 다음 비행`이 한 흐름으로 보이게
5. **뒤로 미룬다(지금 하지 않는다):** IFC 업로드 UI · 균열 탐지 UI · 박락·부식·
   백화 추가 학습 · Dock/다기체. 폐루프 완주 뒤에 재개한다.

## 완료 판정 규율 (이 ADR 이후 모든 보고에 적용)

"완료 N건"으로 뭉뚱그리지 않는다. 완료는 다섯 등급으로 구분해 보고한다:

| 등급 | 의미 |
|---|---|
| Product Ready | 사용자가 화면에서 실제 사용 가능 |
| Backend Ready | 계산/API/worker까지 완료, 화면 없음 |
| Edge Ready | Manifold용 구현 완료, 실기 미검증 |
| HIL Proven | 실제 DJI 하드웨어에서 검증 |
| Field Proven | 실제 비행에서 종단 검증 |

지금 가장 중요한 지표는 완료 개수가 아니라 **Field Proven이 몇 개인가**다
(2026-08-14 기준 0).

## 병목의 정확한 이름

"매니폴드 네트워크 연결 하나"가 아니라 **"Manifold 3 실기 Runtime/HIL 미검증"**
이다. 네트워크는 첫 관문일 뿐이고, 검증 사슬은 여섯 단계다: ① DPK 실기 기동 →
② M4D PSDK 데이터 수신 → ③ 임무 계약 수신 후 수집 루프 가동 → ④ 촬영·품질판단·
재관측 판단이 실제 기체에서 동작 → ⑤ 비행 중 데이터가 Pilot Cloud 등으로 지상
도달 → ⑥ 통신두절에도 onboard loop 지속·복구.

주의: 서버→Manifold 하향 명령(Cloud MOP)의 M4D 지원은 DJI 문서상 확정 불가
(명시 지원 기종은 Matrice 400) — 당연히 되는 것으로 가정하지 않고 별도 실증
항목으로 남긴다(ADR-KSI-004 갱신과 일치).

## 결과

- `00_SYSTEM_OVERVIEW.md`가 전체 구성도와 두-폐루프 원칙의 한 장 정본이 된다.
- MASTER_PRD §25의 Phase 3 원문은 수정하지 않고 본 ADR이 개정을 기록한다
  (PRD는 FROZEN — 개정은 ADR 계층에서 누적하는 기존 관례를 따른다).
- 다음 실기 세션의 목표는 P0 여섯 단계 사슬의 ①~③이다.
