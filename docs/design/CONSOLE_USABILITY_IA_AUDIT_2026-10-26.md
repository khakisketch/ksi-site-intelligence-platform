## 0. 먼저 — 이번 감사의 결론

현재 콘솔은 **화면은 갖췄지만 업무가 끝까지 이어지지 않는 구간**이 있다. 특히
`자료`·`구역 자료 준비`·`관측 자료 등록`은 이름과 실제 동작이 다르거나, 다음 행동이
다른 화면에 숨어 있다. 이것은 색·간격·카드 모양의 문제가 아니라 **정보구조와 흐름의 문제**다.

가장 심각한 세 가지:

1. **만료 미리보기의 1차 복구가 막다른 길이다.**
   `구역 자료 준비에서 확인` → 도착한 `구역 자료 준비` 페이지에는 **새 준비 요청 버튼이 없다.**
   실제 요청 생성은 `자료` 화면의 선택 자료 정보 안 `이 자료 받기 요청`에만 있다.
2. **자료를 골라도 미리보기를 볼 수 없다.**
   모바일 전체 시트에서 `A로 보기`를 누르면 URL만 바뀌고 시트가 그대로 열려 있다.
   `적용`·`보기` 버튼이 없어 사용자가 `닫기`를 따로 눌러야 한다(닫기가 유일한 적용).
3. **`자료` 탭을 눌러도 자료 목록이 나오지 않는다.**
   첫 자료가 자동 선택된 뷰어와 만료 안내가 먼저 나오고, 목록은 작은 ☰ 아이콘 뒤에만 있다.
   “자료를 고르러 왔다”는 사용자의 기대와 화면이 다르다.

## 1. Critical — 업무 완료를 막는 흐름

### U-01. 만료 복구 CTA가 준비 요청을 만들 수 없는 화면으로 보낸다 — Critical

- 재현: `자료` → 만료된 정사영상 → `구역 자료 준비에서 확인` → `구역 자료 준비`.
- 관찰: 도착 페이지의 주 버튼은 `요청 이력 불러오기` 하나뿐이다. `새 요청`·`준비 요청`은 없다.
  요청 생성 컴포넌트는 `spatial-assets`의 **선택 자료 정보** 안에만 있다.
- 사용자 비용: 만료된 자료를 복구하려면 다시 `자료`로 돌아가 목록을 열고, 자료를 고르고,
  정보를 열고, `이 자료 받기 요청`까지 내려가야 한다. 1차 CTA가 일을 끝내지 못한다.
- 근거: `requests-no-create-390.png`, `requests-controls`에서 main 버튼은
  `["요청 이력 불러오기"]`뿐.
- 방향: 만료 CTA를 **그 자료의 준비 요청으로 직접 연결**하거나, 준비 페이지에
  자료 선택 + 요청 생성 패널을 둔다. 이력 페이지는 이력만의 역할로 둔다.

### U-02. 모바일에서 자료를 선택해도 전체 시트가 미리보기를 계속 가린다 — Critical

- 재현: 390px `자료` → `목록` → `A로 보기`.
- 관찰: `#workbench-catalog`가 `display:flex`로 남아 있고, 374×771 전체 높이를 그대로 차지한다.
  `적용`·`선택 완료`·`이 선택으로 보기`가 없다. `닫기`만 유일한 다음 행동이다.
- 사용자 비용: 자료를 고른 뒤 결과를 보려면 시트를 닫는 동작을 **추론**해야 한다.
  A/B를 연속 선택하는 경우에도 선택 결과(미리보기)를 볼 수 없다.
- 근거: `sheet-after-select-390.png`; `flows.log`의 `sheetAfterSelectA: true`.
- 방향: 모바일에서는 선택 후 시트를 닫고 미리보기로 돌아가거나, 하단에
  `이 선택으로 보기`를 둔다. 데스크톱은 연속 선택을 위해 열어 두는 현재 동작을 유지한다.

### U-03. `자료` 탭의 첫 화면에 목록이 없고, 목록 버튼은 아이콘뿐이다 — High

- 재현: `자료` 탭 진입.
- 관찰: 첫 자료가 자동 선택된 뷰어·만료 안내가 먼저 보인다. 목록은 `목록` 버튼을 눌러야만
  열리며, 390px에서 버튼 라벨은 `sr-only`라 보이지 않는다.
- 사용자 비용: “자료를 고르러 왔다”는 사용자는 화면에 목록이 없다고 판단한다.
  A/B를 고르려면 아이콘을 먼저 눌러야 한다는 것을 학습해야 한다.
- 근거: `materials-initial-390.png`; `initialListButtons: 1`(버튼은 있으나 라벨 비노출).
- 방향: 모바일에서는 라벨 `자료 목록`과 건수를 노출하고, 첫 진입 시 목록을 열거나
  “목록에서 자료를 고르세요”를 1차 행동으로 둔다.

### U-04. `자료 등록`은 파일 업로드가 아니라 관측 작업 생성이다 — High

- 재현: `자료` → `자료 등록`.
- 관찰: 도착 페이지는 `관측 자료 등록`이지만 실제 입력은 `작업 이름`과 `작업구역`이고,
  파일 입력은 없다. CTA는 `관측 자료 등록 계속`이고, 안내문에
  “계속하면 작업이 만들어집니다. 파일은 다음 화면에서 제출합니다.”라고 되어 있다.
  이후 작업 상세에서 파일을 올린다.
- 사용자 비용: “자료를 올리려고” 버튼을 누른 사용자가 작업 이름을 먼저 만들라는 요구를 받는다.
  등록이 두 단계라는 사실을 CTA 라벨에서 알 수 없다.
- 근거: `registration-form-1440.png`; 페이지의 `작업 이름`·`작업구역` 필드와 파일 필드 부재.
- 방향: `관측 작업 만들기`와 `파일 제출`을 분리해 이름을 맞추거나, 한 흐름 안에서
  작업 생성→파일 선택→검토를 단계로 보여 준다. `자료 등록` 라벨은 파일 업로드 화면에만 쓴다.

### U-05. 전역 메뉴에 ‘검토/확인’ 목적지가 없다 — High

- 관찰: 전역 내비게이션은 `홈 / 현장 / 업무`(모바일은 `홈 / 현장 / 업무 / 계정`)다.
  분석 검토·외부 결과 검토·재관측 승인을 모은 목적지가 없다. `받은 업무`는 배정·공유 알림만
  다루며 분석 결과 검토 대기열이 아니다. 리뷰는 홈 카드, 현장 `결과`, 작업 상세에 흩어져 있다.
- 사용자 비용: 여러 현장의 검토 대기 건을 한곳에서 볼 수 없고, 홈에서 안건이 보이지 않으면
  어느 현장으로 가야 할지 알 수 없다. 제품의 핵심 업무(검토)가 메뉴에서 보이지 않는다.
- 근거: 전역 nav 링크는 `홈·현장·업무·도움말·계정`뿐; `받은 업무` 항목 타입은
  `WORK_ORDER_ASSIGNED`·`EXTERNAL_REPORT_SHARED` 두 가지(분석 검토 아님).
- 방향: `검토`(또는 `확인 항목`)를 전역 4번째 업무 목적지로 두고, 분석·외부 결과·재관측
  승인을 한 큐로 모은다. 계정·도움말은 유틸리티로 내린다. ADR-026의 전역 IA와도 정합.

## 2. High — 반복 마찰·맥락 상실

### U-06. 작업 상세에 전역 업무 탭이 남아 있어 상세 맥락을 깨뜨린다 — High

- 관찰: `/field/work-orders/[id]` 상세에서도 `받은 업무 / 전체 관측 작업 / 팀 관리` 탭이
  그대로 보인다. 활성 탭은 `전체 관측 작업`이다. 상세에서 탭을 누르면 작업을 떠난다.
- 근거: `work-order-detail-390.png`, `workOrderTabs` = 세 탭.
- 방향: 상세에서는 전역 탭을 제거하고 `‹ 전체 관측 작업` breadcrumb/back만 둔다.
  탭은 목록 화면에만 둔다.

### U-07. 모바일 시트에 A/B의 의미와 현재 선택이 설명되지 않는다 — High

- 관찰: 시트에는 `A로 보기`·`B에 두기`만 있고 `A`/`B`가 무엇인지, 첫 자료가 자동 A인지
  설명이 없다. 무대의 “두 시점을 나란히...” 안내는 시트 뒤에 가려져 있다.
- 근거: `sheet-after-select-390.png`; 시트 상단에 역할 설명 없음.
- 방향: 시트 상단에 `비교할 두 자료를 A(왼쪽)·B(오른쪽)로 고릅니다` 한 줄과
  현재 A/B 이름을 표시한다. 자동 선택은 `자동 선택됨`으로 명시한다.

### U-08. 934px 노트북이 “노트북에서 계속”으로 막힌다 — High

- 관찰: 934px 창에서 `/observations/new`는 폼 대신 `노트북에서 계속` 안내만 보여 준다.
  실제 판정은 viewport 1024px 기준이라, 노트북 사용자는 창을 넓혀야 한다는 것을 알 수 없다.
- 근거: `registration-blocked-934.png`.
- 방향: `화면 폭 1024px 이상에서 계속할 수 있습니다`처럼 **원인과 해결**을 말한다.
  기기 종류가 아니라 창 폭 기준임을 명시한다.

### U-09. 작업구역 등록이 `설정·정보` 안에 숨어 있다 — Medium

- 관찰: 자료 등록의 전제인 작업구역 관리는 사이트 헤더 `설정·정보` → `작업구역 관리`에만 있다.
  `작업공간`/`자료`의 1차 행동에는 없다.
- 근거: 사이트 헤더 설정 메뉴 링크 목록.
- 방향: 작업구역이 없을 때 `작업공간`·`자료`의 빈 상태에 `작업구역 만들기`를 1차 행동으로
  노출한다. `설정·정보`는 보조 경로로 유지한다.

### U-10. `작업공간`과 `자료`의 역할 차이가 화면에서 드러나지 않는다 — Medium

- 관찰: 두 탭 모두 선택 자료·만료 안내·정보 패널을 보여 준다. `작업공간`은 공간 개요·관측
  선택, `자료`는 등록 자료 뷰어라는 차이가 첫 화면의 제목·행동만으로는 구분되지 않는다.
- 근거: `materials-initial-390.png`와 `workspace-390.png`의 첫 화면 유사성.
- 방향: `작업공간`은 “공간에서 보기”, `자료`는 “파일 목록·준비 상태”로 첫 화면의 1차 행동과
  빈 상태 문구를 분리한다.

### U-11. 관측 작업 목록에 ‘내 작업’/담당 필터가 없다 — Medium

- 관찰: `전체 관측 작업`은 검색·현장·상태만 있고 담당자 필터가 없다. 담당·기한은 표시되지만
  “내가 처리할 작업”을 좁힐 수 없다. 개인 업무는 `받은 업무`로 따로 가야 한다.
- 근거: `work-1440.png`의 필터; `받은 업무`와 `전체 관측 작업` 분리.
- 방향: `내 작업`/`담당자` 필터를 추가하거나, `받은 업무`와 `전체 관측 작업`의 관계를
  탭 설명에 명시한다.

### U-12. 준비 요청 이력이 길고 반복적이며, 생성 경로가 보이지 않는다 — Medium

- 관찰: `구역 자료 준비` 이력은 동일한 `Floreat … · 정사영상 · 촬영 구간 미기재` 행이
  반복되고, 새 요청 버튼이 없다. 12건이 한 목록에 쌓인다.
- 근거: `requests-no-create-390.png`, `requestLinks`.
- 방향: 요청 생성 CTA를 상단에 두고, 이력은 상태·종류·기간으로 묶는다.

## 3. Low / 추가 확인

- `검사 완료 4`는 “파일 검사 기록”이지 “미리보기 준비/분석 가능”이 아니다. 만료 상태와
  함께 보이면 준비 완료로 오독될 수 있다. `파일 검사 완료`로 명시한다.
- 자료 시트가 전체 화면을 덮을 때 사이트·작업구역 이름이 사라진다. 시트 헤더에
  `Floreat … · 작업구역` 부제를 둔다.
- 목록 행에 `headline` 링크와 `A로 보기`가 같은 목적지로 중복된다. A/B 두 행동만 남기고
  제목은 텍스트로 두는 편이 스캔이 빠르다.
- `받은 업무` 기본값이 ‘읽지 않음’이라, 처음 방문한 사용자는 빈 화면을 보고 전체 업무가
  없다고 오해할 수 있다. 빈 상태 문구는 있으나 탭 라벨에 `(읽지 않음)`을 붙이는 편이 낫다.

## 4. 잘 되어 있는 부분

- 만료·권한·미확인을 0이나 정상으로 바꾸지 않고, 복구 문구를 제공한다.
- A/B 선택은 URL로 유지되고, exact reference를 잃지 않는다.
- 현장 등록은 단계·검토·초안 복원이 명확하다.
- 작업 목록의 검색·상태 필터와 모바일 하단 내비게이션은 안정적이다.
- 홈의 검토 카드는 실제 분석 기록으로 직접 연결된다(도착지 자체는 정확).

| P1-3 | 작업 상세에서 전역 업무 탭 제거 | 상세 맥락 유지 |
| P2-1 | A/B 역할·현재 선택 설명 | 비교 진입 장벽 |
| P2-2 | 1024px 게이트 문구·작업구역 빈 상태 | 노트북/첫 설정 마찰 |
| P2-3 | 준비 요청 이력 그룹화·생성 CTA | 반복 목록 정리 |

## 6. 아직 확인하지 못한 것

- 실제 파일 업로드·검사 완료까지의 전체 성공 흐름(실데이터 만료).
- 분석 요청 제출·검토 승인·재관측 초안 승인.
- 느린 네트워크/오프라인, 권한 만료, 동시 편집.
- 스크린리더·물리 터치·키보드만으로 전체 여정.
- 여러 현장·여러 사용자 규모에서 검토 큐의 우선순위.

이 문장은 최초 감사 시점의 범위다. 아래 9.1의 P0-1·P0-2는 2026-10-26에 구현·배포했고,
나머지 항목은 아직 코드 변경 전이다.

## 9.1 구현 상태 (2026-10-26)

- **P0-1 (자료 화면)**: 만료 미리보기의 CTA를 `선택 자료 정보에서 준비 요청`으로 바꿔,
  이력 페이지가 아니라 그 자료의 정보 서랍(준비 요청 폼)을 연다. 요청 이력 페이지에는
  `자료에서 새 준비 요청` CTA와 빈 상태 CTA를 추가해 생성 경로를 노출했다.
  두 칸 비교가 모두 만료된 경우는 어느 한쪽으로 좁히지 않고 기존처럼 이력으로 보낸다.

## 8. Home·메뉴 구조 제안 (2026-10-26)

- **현장 > 업무**: 그 현장의 전체 관측 작업 원장(회차·담당·기한·상태·재관측 제안).
- **전역 > 내 업무**: 나에게 배정·공유된 항목만 투영. 행을 열면 현장 업무의 작업 상세로 이동.
- **전역 > 검토**: 분석 결과·외부 결과·재관측 승인처럼 사람이 결정할 항목만 투영.
- **전역 > 현장**: 장소 디렉터리. 현장 > 공간/업무/자료/결과가 장소의 문맥을 소유.
- **홈**: `전체 N곳 · 확인 필요 M곳` → 현장당 한 건의 `확인이 필요한 현장` →
  필요한 경우 `초기 설정이 필요한 현장` → `최근 업데이트`. `내 업무` 목록을 복제하지 않고
  바로가기만 둔다. ADR-025 D1/D4/D7의 중복 금지·순서를 유지한다.
- **모바일**: 홈/현장/내 업무/검토/계정 5탭, 현장 안은 공간/업무/자료/결과 4탭.
  작업 상세에는 전역 업무 탭을 두지 않고 `‹ 전체 관측 작업` breadcrumb만 둔다.

시각 보드: `docs/design/CONSOLE_USABILITY_REDESIGN_PROPOSAL_2026-10-26.html`의 섹션 00.
이 제안은 아직 구현되지 않았고, Core·권한·원장은 변경하지 않는다.


## 9. 공간 중심 시각 방향 (2026-10-26)

기존 제안이 여전히 텍스트·표 중심이라는 지적을 반영해 별도 시각 보드를 만들었다:
`docs/design/CONSOLE_SPATIAL_VISUAL_DIRECTION_2026-10-26.html`.
- 홈: 지표 카드 대신 두 현장의 실제 범위 도식이 캔버스가 되고, 확인 필요·상태·다음 행동은
  타일 위에 한 번만 둔다.
- 현장: 큰 공간 캔버스, A/B 범위, 시간선, 얇은 우측 정보. 만료는 거대한 빈 사각형이 아니라
  캔버스 안의 짧은 상태와 `이 자료 준비 요청`으로 표현한다.
- 현장 업무: 현장 안의 전체 원장. 짧은 행과 단계 레일.
- 모바일 자료: 파일명 리스트가 아니라 실제 범위 타일 그리드 + 큰 범위 시트.
- 전역은 `홈/현장/내 업무/검토`, 현장은 `공간/업무/자료/결과`; 전역은 나의 큐, 현장은
  장소의 전체 원장.
- 배경·표면은 기존 콘솔의 중립 회색·흰색 토큰을 그대로 쓴다(`#f6f7f8`, `#ffffff`,
  `#e0e2e5`, `#bfc3c8`, `#121417` 계열). 제안 단계에서 임의로 넣었던 따뜻한 종이색은
  제거했다. 공간 도식의 강조는 중립 blue-gray 한 색만 쓰고, 경고·만료·검토 상태색은
  기존 의미를 유지한다.
- 화면 테마 선택은 이번 범위가 아니다. 배경을 바꾸지 않고, 향후 `설정 > 화면 테마`에서
  결정할 항목으로 남긴다.
- 사진·가짜 위성영상은 쓰지 않는다.
- 이 파일은 시각 방향 제안이며 운영 코드가 아니다. 운영 이미지·Core·권한은 변경하지 않았다.


## 10. 데스크톱 우선 설계 (2026-10-26)

`docs/design/CONSOLE_DESKTOP_FIRST_2026-10-26.html` — 1440×900 기준의 인터랙티브 시안.

- 홈: 두 현장의 실제 등록 범위 도면과 다음 행동을 가진 포트폴리오. 확인 필요는 한 번만.
- 전역 레일: `현장` 아래에 **현재 현장만** 펼치고 `공간 / 자료 / 업무 / 결과`를 둔다.
  현장명을 누르면 현장 변경 팝오버가 열리고, 다른 현장은 거기서 고른다. 모든 현장을
  항상 트리로 펼치지 않는다 — 현재 문맥과 전환만 남긴다. 사이트 헤더의 중복 탭은 없앴다.
- 현장 공간: 왼쪽 관측 레일 · 큰 공간 캔버스 · 오른쪽 선택 정보의 3분할. 만료는 큰 빈
  사각형이 아니라 범위·치수·축척 위의 짧은 상태와 준비 요청으로 둔다.
- 자료: 목록 · 무대 · 정보가 동시에 보이는 3분할. 데스크톱에서 목록을 서랍 뒤에 숨기지 않는다.
- 내 업무: 전역 큐는 현장 업무의 투영으로 분리하고, 현장 업무는 현장 안의 원장으로 둔다.
- 실제 Floreat 작업구역 255.5 × 228.8 m, Sample 100 × 100 m를 사용했다. A/B 준비 창은
  512 × 512 px이며, 픽셀 이미지 없이 범위·치수·축척만 표시한다. 가짜 사진은 쓰지 않았다.
- 이 파일은 디자인 시안이며 운영 코드가 아니다. Home 구조 변경은 ADR-025 D6/D7,
  전역 메뉴는 ADR-026의 승인 범위를 확인한 뒤 적용한다.
