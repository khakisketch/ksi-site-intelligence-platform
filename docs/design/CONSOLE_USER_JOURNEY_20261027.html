Console 사용자 여정 지도 — 현장 진입에서 다음 관측까지

현장 공간 상태를 탐색하는 작업공간으로서의 Console이 한 명의 사용자를 현장 진입부터 자료 발견, 영역·관측 선택, 지원 분석, 결과·근거·제한 검토, 반복과 다음 관측까지 데려가는 길을 한 장에 정리한 경험 지도다. 길을 읽는 용도이며, 새 endpoint·권한·배포·수용을 만들지 않는다.

이 지도가 다루는 일

사용자는 “지난번보다 얼마나 파고 쌓았나” 같은 작업 언어로 묻고, Console은 등록된 파생 산출물과 고정된 작업구역, 두 시점 관측을 근거로 답하는 쪽으로 이끈다. 이 지도는 그 한 바퀴를 끊기지 않게 보여주는 것이 목표다.

성공은 같은 구역·같은 두 관측을 가리키는 하나의 Core 계산 기록에 유효 범위·제외·미확인 범위·입력 날짜·정량 제한을 함께 얹어 도달하는 것이다. 피할 실패는 셋이다 — 지원하지 않는 질문을 지원되는 계산으로 바꿔 답하기, 모르는 영역을 0·추정으로 메우기, 권한·자료·정확도 상태를 실제보다 좋게 보이기.

전체 흐름 지도 — 외부 작업 경로

외부 AI와 대화하던 사용자가 Console로 건너와 영역을 확정하고 다시 외부 작업으로 돌아가는 길이다. Console 주 경로와 출발지가 다르므로 같은 선으로 합치지 않았다. 외부 AI는 흐름을 조율할 뿐 경계·권한·측정 사실의 권위가 되지 않는다.

전체 흐름 지도 — 중단·복구와 반복

끊겼다 돌아오는 길이다. 페이지가 유지된 채 가시성·포커스를 되찾을 때에 한해 작업 화면의 미저장 선택을 로컬로 유지하며(저장 아님, 다른 폼 적용 불확실), 화면 이동·언마운트·새로고침·로그인하면 보장 없다. 서버가 바뀌었으면 덮기 전에 알리고, 좁은 화면에서는 등록·작업 선택 저장·분석 요청을 제한한다.

단계별 상세 — 무엇을 보고 무엇을 하는가

도면의 각 칸을 펼쳤다. 보는 화면, 하는 일, 막혔을 때의 행동, 그리고 그 말이 어떤 근거 문서에서 왔는지를 함께 둔다. 근거 표기는 실행 코드가 아니라 문서 권위를 가리킨다.

0현장 진입 — 내 현장을 고르고 작업공간에 선다

보는 화면
홈·현장 목록(준비된 미리보기가 없으면 16:9 중립 커버 — 사진도 범위 주장도 아님), 현장 안에서는 작업공간·자료·관측 작업·결과 섹션.
하는 일
현재 현장 하나를 고른다. 현장을 바꾸면 보던 섹션을 유지한 채 이동한다(현장 변경 시트, 좁은 화면에서는 네이티브 모달).
막혔을 때
권한 밖 현장은 목록에 섞지 않고, 만료·무효는 상태를 가리지 말고 드러낸다. 전역 “내 업무·검토” 갈라보기는 승인·증거 전제이므로 이 지도에 그리지 않는다.

근거: CONSOLE_CURRENT_SPEC 한 화면 모델 · DESIGN 결정 유지

1자료 발견·등록·검사 — 남의 원본이 아닌 제출된 산출물을 다룬다

보는 화면
자료 탐색(넓은 화면은 viewer-first 무대 + 닫힘 상태로 시작하는 도킹 카탈로그), 선택 자료 인스펙터(제목·상태·핵심 사실·다음 행동 우선, 내역은 상세 정보 아래).
하는 일
고객이 자기 장비에서 재구성해 제출한 파생 산출물의 등록·검사 상태를 확인한다. 원본·재구성 실행은 고객 소유이며 KSI는 제출물을 등록·검사·허용 활용한다.
막혔을 때
정사영상만 등록될 수 있고, DSM 등 근거가 빠지면 종속 주장을 제한한다(전부 막는 것이 아님). 준비되지 않은 무대는 가짜 그림 대신 등록된 범위와 준비 창 경계를 그린다.

근거: CONSOLE_CURRENT_SPEC 자료·인스펙터 · ADR-KSI-036 D4/D5(정사 단독 허용)

2영역·관측 선택 — 무엇을 무엇과 비교할지 확정한다

보는 화면
이름 있는 작업구역 후보(이름·경계 미리보기), 관측 쌍 선택(기준 시점 t0→t1 순서, 겹치지 않는 촬영 구간), 지도 위 선택 화면.
하는 일
이미 확정된 구역을 그대로 쓰거나(보통 반복 요청에는 새 승인 절차 없음) 이름으로 고른다. 이 외부 작업의 재개는 기존 승인 구역만 다루며, 이 작업 안에서 구역 참조 확대·권한 확대는 미지원이다. 별도로, 권한 있는 사용자는 Console 작업구역 관리 흐름에서 구역을 생성·대체할 수 있으나, 이는 기존 외부 작업의 참조를 넓히거나 과거 불변 형상을 바꾸지 않는다.
막혔을 때
“동측”처럼 여러 구역에 걸리는 표현은 고르게 묻고, 등록된 이름·방위 근거 없는 영역은 꾸미지 않는다. 관측 시각과 제출·처리 시각을 구별하고 날짜만 아는 자료에 시각을 만들지 않는다.

근거: 외부 작업 여정 영역 3경로 · 첫 요청 계약 epoch·구역 조건

3지원 분석 — 첫 분석 사례의 조건 안에서만 계산한다

보는 화면
분석 intake(조건·증거·동결 조건), 준비·계산 작업 상태(대기·진행·완료·보완 필요), 같은 식별자로 재시도하는 실행 화면.
하는 일
구역별 주간 2시점 관측 지형 물량 변화라는 첫 목적에 맞는 요청을 만든다. 두 epoch의 적격 DSM, 고정 구역·호환 조건이 모두 서야 계산 기록이 생긴다.
막혔을 때
“설계까지 얼마나 남았나”“오늘 얼마를 해야 하나”는 이 계산으로 답하지 않고 각 목적의 다음 행동(설계면 선택 등)으로 돌린다. 조건 부족은 raw 오류 대신 그 목적의 구체적 다음 행동으로 안내한다.

근거: 첫 요청 계약 목적·동결 조건 · 외부 작업 여정 질문 구분

4결과·근거·제한 검토 — 숫자와 함께 경계·날짜·제한을 본다

보는 화면
결과 화면(list/form-first 밀도): 절토·성토·순수량, 잠정치 표시, 유효·제외·미확인 범위, 입력 날짜와 근거 참조. 지도는 경계 중심이며 격자는 정확한 커버리지·위치 근거와 함께 on-demand로 본다.
하는 일
같은 Core 결과 ID·revision을 확인하고, 체크포인트 평가가 없으면 잠정치(uncertainty 없음)로 읽고, 통과 평가가 있으면 그 평가 증거 그대로 함께 본다. 완성은 검토·발행이 아니다.
막혔을 때
평가 실패·충돌이면 보통 숫자 공개를 멈추고 remediation-required와 보완 경로를 보인다. 이전 계산은 원래 평가 스냅샷과 함께 역사적 결과로만 조회되며 조용히 바뀌지 않는다.

근거: 첫 요청 계약 결과·차단 표 · CONSOLE_CURRENT_SPEC 결과 연결

5반복·다음 관측 — 같은 구역과 규칙으로 다음 바퀴를 돈다

보는 화면
같은 구역·매핑·규칙을 재사용하는 다음 요청 화면, 새 자료의 새 조건 점검과 새 결과 기록.
하는 일
새 관측(t1→t2)에는 새 입력-bound 승인·권한·결과 기록을 만든다. 이전 쌍의 매핑·승인·입력을 재사용하지 않으며, 같은 자료·digest의 검증된 증거만 정책 안에서 참조한다.
막혔을 때
공식 기준 변경·결과 발행은 사람 게이트이며 일반 계산 완료와 별개다. 새 조건이 서지 않으면 새 숫자를 만들지 않는다.

근거: 첫 요청 계약 주간 재사용·승인 게이트

갈라지는 길 — 외부 작업과 수동 분석은 다르다

연구에서 서로 다른 길이 나왔으므로 하나로 합치지 않는다. 출발지가 다르고, 만나는 점은 같다: 같은 구역 참조, 같은 관측 revision, 같은 Core 결과 기록.

갈림외부 작업 경로Console 수동 경로
출발외부 AI 대화에서 작업 언어로 질문Console 현장·자료 화면에서 직접 시작
영역 확정Console 선택 전달 / 이름 있는 기존 구역 선택 / 지도 링크로 좁은 선택 화면 → “이 구역으로 계속” → 확정 참조 조회 재개. 다른 브라우저 화면을 AI가 안다고 가정하지 않음. 이 작업 안에서는 새 구역 확정·권한 확대 미지원Console 안에서 기존 확정 구역 재사용·이름 선택(이 외부 작업 재개는 기존 구역만 — 별도 관리 흐름의 구역 생성·대체와 무관)
이어지는 상태인증된 현장·작업 의도·구역 참조·관측 revision·자료 기준 시점·작업 ID를 연결(조율 상태, 권위 아님)같은 화면 안에서 선택·준비·결과가 이어짐
결과외부 대화와 Console이 같은 Core 결과를 가리킴. 모르는 영역 0 채우기·AI 수량 추정 금지같은 Core 결과 ID·근거 참조·제한을 같은 화면에서 검토

막힘과 회복 — 여덟 갈래

각 갈래는 실제 화면에서 일어나는 일과 그때의 회복을 한 줄로 묶었다. 적힌 행동 너머의 해결을 약속하지 않는다.

갈래사용자가 겪는 일회복
권한·만료작업·지도·결과가 안 열림(401/403/404/410)비공개 대상을 가리고, 0이나 빈 수치로 대체하지 않음. 읽기 전용 재시도 제공
자료 없음관측·DSM·좌표·공통 영역 조건 미달영역·요청 자료·사유·상태만. 좌표·수량·신뢰도·승인을 꾸미지 않음

미지원 목적설계 잔여량·오늘 작업 목표 질문관측 간 변화로 몰래 대체하지 않고, 그 목적의 다음 행동(설계면 선택 등)으로 안내
중단·복귀나가거나 끊기고 돌아옴페이지가 유지된 채 가시성·포커스를 되찾을 때에 한해 작업 화면의 미저장 선택을 로컬 유지(저장 아님). 화면 이동·언마운트·새로고침·로그인·다른 폼 보장 없음. 복귀 읽기가 새 저장·새 계산을 덮지 않음. 만료·권한 상실 시 허용 부분만 복구
등록 응답 미확인관측 작업 등록 요청 뒤 접수 여부를 확인하지 못함이 폼을 유지한 채 같은 계정으로 기존 요청을 다시 시도하거나 작업 목록에서 먼저 찾는다. 신원을 확인하지 못하면 새 요청을 시작하지 않고, 다른 계정·조직으로 바뀐 같은 요청은 작업 생성 전에 막는다. 이 보호는 다른 호출 경로나 새 요청까지 보장하지 않는다. 화면을 떠나거나 새로고침하면 입력과 기존 요청이 사라질 수 있다.
이전 사용 판정 응답 미확인이전 비교 흐름에서 확인 요청 뒤 접수 여부를 확인하지 못함이 화면에 남아 있는 원래 요청은 같은 계정·같은 내용으로 재시도한다. 다른 계정·조직이 같은 요청을 보내려 하면 판정 전에 막고, 이전 처리 여부는 추정하지 않는다. 조건을 바꿔 새 요청을 시작할 때는 별도 기록이 생길 수 있음을 먼저 알린다. 이 보호는 다른 호출 경로나 새로고침 후까지 보장하지 않는다.
불확실성체크포인트 평가 없음 / 실패·충돌없으면 잠정치(uncertainty 없음)로 읽고, 실패·충돌이면 신규 일반 공개 중단(remediation-required)과 보완 경로 — 이전 기록은 원래 평가 스냅샷으로 역사적 조회만. 등록·RTK FIX·소프트웨어 검사는 정확도·정산 적합이 아님

범위 구분 — 배포 화면 · 로컬 개선 · 외부 경계

배포된 화면과 아직 배포하지 않은 로컬 후보를 구분한다. 구현과 로컬 검증은 고객 인수나 운영 승인을 뜻하지 않는다.
