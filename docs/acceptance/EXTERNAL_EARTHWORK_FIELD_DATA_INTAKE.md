# 첫 토공 분석 제품 — 고객 자료 준비 패킷

상태: **요청 양식만 준비됨.** 2026-09-28 현재 사용자에게 실제 Terra DSM·처리 보고서가 없다. 자료 입수, 호환성, 정확도, 현장 수용은 아직 검증되지 않았다. 정본 범위는 [ADR-KSI-036](../architecture/ADR-KSI-036-customer-reconstruction-and-result-ingress.md), [ADR-KSI-037](../architecture/ADR-KSI-037-api-first-earthwork-evidence-and-integration.md), [첫 요청 계약](../design/API_FIRST_EARTHWORK_FIRST_REQUEST_CONTRACT.md)이다.

같은 현장의 **한 WorkArea, 세 관측 시점 `t0,t1,t2`**에 대해 다음을 받는다. 먼저 `t0,t1`만 확보되면 첫 분석 호환성 검토를 시작할 수 있고, 다음 주 재사용 수용에는 `t2`가 필요하다.

| 자료 | 필요한 이유 |
| --- | --- |
| 시점별 고객 도구가 생성한 DSM/terrain GeoTIFF 원본 export와 파일명·크기·SHA-256 | 실제 바이트·격자·CRS·NoData·범위를 검사하고 각 비교의 입력을 고정한다. 정사영상은 위치 확인용 선택 자료다. |
| 시점별 Terra 등의 처리 보고서 및 소프트웨어 버전·설정·처리 완료 시간 | 생산자 선언과 실제 파일 관측을 구분하고 두 시점의 생산 조건을 대조한다. 보고서 내용 자체가 정확도 보증은 아니다. |
| WorkArea 경계와 그 좌표계, 조사 시작/종료 시각, 현장/구역을 연결할 비식별 ID | 동일 공간·순서의 `t0→t1`, `t1→t2`를 선택한다. |
| 수평 CRS, 수직 기준/단위, 적용한 변환·정합 기록 및 각 자료의 출처/버전 | 서로 비교 가능한지 판단한다. 모르는 항목은 추측해 채우지 않고 `미확인`으로 표시한다. |
| 독립 검사점 평가가 있다면 원본 근거·측정 방법·적용 범위·판정 기준 | 정확도 상태를 구분한다. 자료가 없어도 계산 가능 조건은 별도로 판단하지만, 알려진 실패·상충은 잠정 결과로 우회하지 않는다. |
| 제공자/사용 권한 및 보관·AI 반출 허용 범위 | KSI 처리와 외부 에이전트 사용을 고객 허용 범위 안에 둔다. |

원본 사진, 기체 비행 로그, GCP 설치, BIM, LandXML, 설계면은 이 첫 **주간 관측 변화** 분석의 기본 필수 입력이 아니다. 고객이 가진다면 별도 목적과 권한을 확인해 연결한다. RTK FIX 또는 처리 성공만으로 절대 위치·체적 정확도나 정산 적합성을 인정하지 않는다.

파일은 고객이 승인한 비공개 전달 경로에 두고 Git·이 문서·대화에 원본 데이터나 현장 실명·좌표를 기록하지 않는다. KSI는 받은 파일의 해시와 메타데이터를 확인하고, 지원되지 않는 CRS/높이/격자/형식 또는 누락 정보는 구체적인 보완 사유로 돌려준다. 실자료 수용 규격과 수치 사용 범위는 샘플 검증 후 확정한다.

## 고객에게 전달할 간단한 요청

현장 담당자에게는 다음처럼 요청한다.

> 같은 토공 구역을 세 차례 측량한 DJI Terra DSM/terrain GeoTIFF와 각 차례의 처리 보고서를 제공해 주세요. 먼저 두 차례 자료로 첫 비교를 검토하고, 세 번째 자료로 다음 주 반복을 확인합니다. 구역 경계, 조사 날짜, 사용한 좌표계와 높이 기준·단위, 자료 사용 및 보관 허용 범위도 알려 주세요. 독립 검사점 평가가 있다면 함께 제공해 주세요. 정사영상은 위치 확인용으로 있으면 좋지만, 3D Mesh와 Point cloud는 이번 첫 변화 계산에 필수는 아닙니다. 모르는 항목은 추정하지 말고 '미확인'으로 적어 주세요.

파일 전달 경로와 사용 권한은 고객 담당자와 별도로 정한다. 예시 파일이나 현장 좌표를 이 문서 또는 이슈에 붙이지 않는다.

## 고객 IT 담당자에게 전달할 로그인 요청

OIDC는 고객이 평소 사용하는 회사 로그인을 KSI 화면에 연결하는 표준 방식이다. 현장 담당자가 직접 값을 찾거나 새 로그인 서버를 만들 필요는 없다. 고객 IT/보안 담당자에게 다음을 요청한다.

> KSI 첫 파일럿에 회사 OIDC 로그인을 연결하려 합니다. 시험 사용자 1~2명에게 사용할 OIDC 발급자(issuer) URL, KSI API가 검증할 audience와 JWKS URL, KSI 화면용 앱 등록의 client ID 및 허용 redirect URL을 알려 주세요. 시험 사용자의 안정적인 `iss`+`sub` 식별값과 어느 조직·현장·WorkArea에 접근해야 하는지도 확인해 주세요. 비밀값(client secret)은 채팅·Git·이 문서가 아니라 승인한 보안 전달 경로로만 공유해 주세요. 고객 정책상 Tailnet 접근이 가능한지도 확인해 주세요.

KSI는 이 정보를 받은 뒤 발급자 서명·audience·시험 사용자 매핑을 검증하고, 접근을 지정 현장과 WorkArea로 제한한다. 고객사가 OIDC를 제공할 수 없는 경우 임의의 개발용 발급기를 고객 경로에 대신 연결하지 않는다. 실제 앱 등록, 비밀값 설치, Tailnet 및 호스트 설정은 별도 승인과 운영 검증이 필요한 후속 작업이다.
