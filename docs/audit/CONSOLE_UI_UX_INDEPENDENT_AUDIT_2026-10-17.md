# Console UI/UX 독립 종합 검수 — 2026-10-17

## 결론

**명칭과 기본 조작은 개선됐지만, 현장 자료를 이해하고 활용하는 전체 흐름의 사용성은 아직 수용할 수준으로 종결하지 않는다.**
기술적 기본기와 실제 업무 사용성은 다른 결과다. 자동 검사 0건은 잘못된 진입·좌표 표시·정보구조를 보증하지 않는다.

### U05 · P2 — 현장 상세가 실제 공간을 확인하는 작업공간보다 안내 링크 모음에 가까움

- 기본 Site는 시작 안내·건수·다른 페이지를 여는 설명 카드 중심이다. 기존 구역 목록도 이름·시각·ID·꼭짓점만 보인다.
  읽기 전용 사용자는 구역 모양과 자료 범위가 어디인지 확인할 화면이 부족하다.
- 영향: 이름을 읽어도 "어디의 어느 자료인가"를 머릿속으로 연결해야 한다. 사용자의 텍스트 중심 피로와 일치한다.
- 설계: 안전한 CRS 처리(U02) 뒤에 **선택한 구역·인가된 자료 footprint·촬영 시점의 읽기 전용 시각 확인**을 우선한다.
  옆에는 선택 대상의 상태·한계·다음 행동, 아래에는 시점/자료 목록을 둔다. 경고문을 카드마다 늘리는 해법을 피한다.
- 경계: metadata-only catalog가 원본 영상 표시 권한을 주지는 않는다. 정사영상 미리보기/전후영상은
  실제 제공 가능한 인가 리소스가 있을 때만 표시하며, 자료가 없으면 위치/정확도를 추정하지 않는다.
- 이는 **다음 화면 설계 제안**이며 지도·오버레이가 구현됐다는 뜻이 아니다. Home의 승인된 대형 영역은 유지한다.

### U08 · P2 — 시점 선택 변경·잘못된 순서에 대한 피드백 부족

- 순서 A: 기준 t2 → 현재 t1을 고르면 기준이 자동 해제되는데, 일반적인 "서로 다른 관측을 고르세요" 안내만 남는다.
- 순서 B: 현재 t1 → 기준 t2를 고르면 시간 역전 조합인데도 버튼이 켜지고 구체적 경고가 없다.
- 두 관찰은 모순이 아니라 현재 select의 자동 기준 제안과 명시 선택 처리의 차이다. Core 최종 판정은 별도다.
- 설계: 사용자가 직접 고른 값과 자동 제안을 구분하고 변경 이유·현재 빠진 항목을 즉시 설명한다.
  알려진 시간 역전/겹침은 요청 전에 알리되, client 검사로 계산 적합성/정확도를 인증하지 않는다.
- 증거: C F4, `primary/reverse-pair-before-submit.png`, `probes.log`. POST 없이 확인.

### U09 · P2 — 진입 가능성과 도착 후 권한/실패 안내 불일치

- 관리자에게 `현장 등록`을 제공한 뒤 `/sites/new`에서는 등록 권한이 없다고 거부한다(A F4).
  일반 SITES_WRITE와 SITE_BOOTSTRAP capability는 다르므로 역할 이름만으로 가용성을 추정하면 안 된다.
- `/field/team`은 원인 구분 없이 "불러오지 못했습니다 / 다시 시도"만 표시한다. 권한·미구성·일시장애 원인은 미확정이다.
- 설계: 이미 알려진 capability/등록 모드를 진입점에도 적용하고, 알 수 없는 원인은 단정하지 않는다.
  실패 종류에 맞는 복구·작업 복귀를 제공한다. 권한을 늘리거나 무한 재시도하지 않는다.
- 증거: A fresh captures/report, source NewSitePage/FieldTeamPage. 고객 계정/운영 환경에서도 발생한다고 일반화하지 않는다.

### U10 · P2 — 긴 관측 선택값의 구분 정보가 닫힌 select에서 잘림

- 3열 선택 UI의 닫힌 컨트롤에서 촬영 구간 끝·제출 버전이 잘린다. 선택 후 확인 카드는 전체 문구를 보여 준다.
- 영향: 현재 선택을 빠르게 점검하기 어렵다. 다만 native popup 전체 항목이 읽히지 않는다고 입증한 것은 아니다.
- 설계: 읽을 공간을 더 주고, 간결한 주 이름+전체 선택 요약을 함께 유지한다. 검증 없이 custom combobox로 교체하지 않는다.
- 증거: C `08-analysis-pair-selected.png`, primary 역전 선택 캡처.

### U11 · P2 — 제목 구조·반복 설명의 읽기 비용

- 신규 관측 화면의 두 H1, 여러 경로의 동일한 H1/H2 반복이 B DOM에서 확인됐다.
- 같은 보호 문구/준비 건수/다음 설명을 반복하는 부분은 업무 정보보다 읽을 양을 늘린다.
- 설계: 제목은 대상과 목적을 구별하고, 자주 필요한 상태/제한은 노출하되 상세 정책·기술 설명은 목적별로 접는다.
  H1 수 자체를 WCAG 실패라고 단정하거나 핵심 한계를 전부 숨기지는 않는다. SR 실제 영향은 미검증이다.

## 검수 의견 중 채택하지 않은 것 / 기존 강점

- **분석 선택 URL 유실**: 다른 분석을 선택하고 라우팅 완료를 기다리면 `?analysisId=`가 갱신된다.
  source `choose():975`와 `primary/analysis-url-confirmed.log`로 반증했다. 이미 선택된 첫 행 클릭/즉시 URL 조회로 오판하지 않는다.
- **38px 버튼**: 채택된 표준은 fine pointer≥36px/coarse≥44px다. 38px fine-pointer는 위반이 아니다.
  실제 hybrid/물리 touch는 별도 검증 대상이지 무조건 44px로 키울 근거가 아니다.
- **전체 해시가 항상 표시됨**: 요청 selector 기술 정보는 기본 닫힘이고 사람용 두 시점 요약이 별도 존재한다.
  필요한 기술 식별 정보 자체를 없애지 않는다. 복사 도움은 낮은 우선순위다.
- **Home 도형을 실데이터 오표시로 단정**: 이미지 없음이 명확히 표시된다. 도형 형태는 취향/저신뢰 P3로만 남긴다.
- 이전 raw epoch 중심 선택지는 현재 **작업명·촬영 구간·버전**으로 개선됐다. 과거 캡처의 문제를 현재 문제로 재보고하지 않는다.
- 표본 가로 넘침 0, 충분한 computed contrast, 표본 keyboard/skip-link, touch login/nav tap과 조회 권한 처리는 유지할 강점이다.
- detector 출력은 0건이며 부모는 재실행하지 않고 B 결과를 재사용했다. 이 값은 위 업무 결함을 부정하지 않는다.
