# KSI 공통 공간 작업환경 — 화면 레퍼런스 조사와 구조 제안

2026-10-23 · **조사/설계 제안, 미구현**. 제품 수용 또는 배포 완료 기록이 아니다.

## 무엇을 바로잡는가

사용자 최신 방향: 웹은 제출된 공간자료를 등록하고 시각적으로 탐색·비교·검토하는 곳이다.
API/MCP를 통한 에이전트와 웹은 같은 Core/워커의 자료·분석·근거를 사용한다. 별도 채팅 UI나
계산 폼을 웹의 중심으로 만들지 않는다. 작업공간/자료/결과를 따로 꾸미는 방식 대신 **공간
뷰어는 유지하고 탐색·비교·결과 맥락을 바꾼다**. 종전의 세 독립 화면·행 펼침 중심안은
이 방향의 최종 시각적 권위가 아니다. 과거 코드/기록을 삭제하거나 재서술하지 않는다.

판단 방법: **task-first-ux-review 적용**. 사용자의 주 작업은 ‘이 현장의 어느 시점에 무엇이
있고 달라졌는지 보고, 자료/결과를 선택하고, 필요할 때 근거를 확인’하는 것이다. 문장 수,
보이는 행 수, 통과 테스트 수만으로 좋아졌다고 판단하지 않는다.

권위: `00_READ_FIRST` → Constitution 제품 정체성 → Decision Ledger → PRD §1.1.2
SDP-REQ-01/02/03/05/06 → ADR-036/037/038/039. 이 문서는 하위 설계 제안이다.
Core·워커 계산/권한/원장 계약, 고객 소유 취득·재구성·촬영 원본 경계는 바꾸지 않는다.

## 조사 범위와 증거 수준

- 실제 KSI: HEAD `a3ceb581`, 실행 이미지 `ksi-product-dashboard:materials-layout-v2-20261023`.

- 일반 웹 검색은 HTTP 402로 실패했다. 공식 도움말 인덱스→해당 문서와 Mobbin 원본을 직접 사용했다.
  Native DOM은 접근됐지만 스크린샷은 visible-tab 오류여서 독립 Playwright CLI로 KSI를 캡처했다.
- 원본/캡처/비교 보드: `/tmp/opencode/ksi-spatial-viewer-research-20261023/`.
  `sources.json`이 공개 원본 URL과 파일 SHA-256을 연결한다. 이 경로는 로컬 증거이며 영구 공개 URL이 아니다.

## 레퍼런스별 관찰 → 사용자 효과 → 채택/제외

### PIX4Dcloud — 레이어 / 뷰어 / 선택 상세의 분업

공식 [Editor viewer](https://support.pix4d.com/hc/editor-viewer-in-pix4dcloud),
[Details panel](https://support.pix4d.com/hc/details-panel).
원본: `primary/pix4d-editor-official.jpg`.

- **관찰:** 공식 화면에 global toolbar, timeline, left Layer Manager, 중앙 viewport,
  right Details panel, bottom status가 명시된다. 선택한 annotation에 따라 우측 정보/행동이 바뀐다.
- **효과/해석:** ‘보이는 것 선택’과 ‘그것의 속성 확인’이 공간에서 분리되지 않는다. 상세를
  문서 페이지로 이동시킬 필요가 없다. 이는 관찰에서 도출한 설계 해석이지 사용자 테스트 결과가 아니다.
- **채택:** 레이어 선택은 왼쪽, 시각 자료는 중앙, 정보는 선택 대상에 따른 오른쪽 패널.
  표시/숨김과 정보 열기를 별개 행동으로 둔다.
- **그대로 채택하지 않음:** 3D·BIM·측정 툴 전체, 높이 수동 보정, 상시 3열 강제, 두꺼운 타임라인,
  다크 테마 자체. KSI는 지원되는 2D부터 시작하고 미지원 3D 토글을 장식으로 두지 않는다.

### DroneDeploy — 비교는 새 폼이 아니라 같은 공간의 모드

공식 [Compare Map Layers Side by Side](https://help.dronedeploy.com/hc/en-us/articles/1500004860801-Compare-Map-Layers-Side-by-Side)
(문서 표시 갱신일 2026-03-11).
원본: `primary/dronedeploy-date-select.png`, `primary/dronedeploy-compare.gif`
(후자는 실제 MIME이 PNG인 정적 이미지).

- **관찰:** primary/comparison 날짜 선택이 뷰어 위 양쪽에 붙고 가운데 슬라이더가 있다.
  문서상 지도가 교차해야 비교할 수 있고, 한 날짜에 없는 레이어는 그쪽에 나오지 않는다.
  비교 보기를 내보내거나 링크 공유하는 기능에도 제한이 명시된다.
- **채택:** 같은 장소를 유지하며 A/B 날짜를 독립 선택하고, 표시 가능한 쌍이면 swipe 비교.
  날짜·레이어·부분 범위가 각 쪽과 명확히 연결된다. 마우스 드래그 외에 키보드 조작도 제공해야 한다.
- **그대로 채택하지 않음:** 겹침만으로 KSI의 비교 적합성을 승인하거나, 보여진 차이를 수치로
  환산하지 않는다. CRS 문자열이 같다는 사실만으로 동기화/정합 완료를 주장하지 않는다.
  비교 공유도 레퍼런스가 지원할 것이라고 추정하지 않는다.

### Propeller — 관측을 바꿔도 지도에서 이탈하지 않는 탐색

공식 [Navigating the Platform](https://help.propelleraero.com/hc/en-us/articles/19383551276311),
[Survey Explorer](https://help.propelleraero.com/hc/en-us/articles/25628038005399).
원본: `primary/propeller-explorer.png`, `primary/propeller-toggle.png`, `primary/propeller-survey-picker.svg`.

- **관찰:** survey picker는 지도 상단에 있고, Survey Explorer는 관측별 레이어를 펼쳐
  켜고 끈다. 선택 관측만 보기, map-view 필터, fly-to가 설명된다. FAQ는 Explorer 레이어의
  표시 변경이 terrain/measurement를 바꾸지 않는다고 명시한다. DEM-only는 목록에 있어도
  Explorer에서 시각화할 레이어가 없을 수 있다고 설명한다.
- **채택:** 관측과 레이어를 연결한 탐색 트리, 지도 위치 유지, 선택 자료의 범위로 이동,
  ‘현재 보임’과 ‘계산 입력’을 분리하는 모델.
- **그대로 채택하지 않음:** 모든 자료를 같은 썸네일/표시로 처리, 자동 최신 관측 선택,
  캡처·terrain 편집·임의 측정. 하단 타임라인이 공통 정답이라는 가정도 버린다.

[원본 화면/Mobbin](https://mobbin.com/screens/29ca2c9d-26a3-4674-93b7-30bb1ff36c7b).
원본: `primary/felt-layers-inspector.webp`.

- **관찰:** 화면 전체에 지도가 남고, 좌측 Legend/List, 우측 선택 group inspector가 뜬다.
  선택 강조와 속성 패널이 같은 대상을 가리킨다.
- **채택:** 기본 뷰포트를 키우고, 상세를 닫으면 즉시 지도 공간을 회복하는 구조. 짧은 범례.
- **그대로 채택하지 않음:** 임의 annotation 편집, 과밀 상단 아이콘, 외부 basemap/데이터 전송을
  권한·라이선스·반출 검토 없이 추가하는 것. 이 화면만으로 날짜 비교 패턴을 추론하지 않는다.

Mobbin의 Figma 화면도 열어 봤지만, 계층/속성 패널의 보조 참고로만 분류했다.

## 제안: 세 페이지가 아니라 하나의 공간 작업환경

**화면의 일:** 현장의 관측과 결과를 공간적으로 보고 선택·비교하고 필요한 근거로 내려간다.

### 항상 보이는 것 / 선택 시 나타나는 것 / 접는 것

- 항상: 한 줄 현장·작업구역 맥락, 자료 등록, 공간 뷰어, 현재 관측·레이어, 부분 범위/표시 한계,
  짧은 범례와 관측 전환. 전역 홈/현장/업무는 펼칠 수 있는 작은 rail로 보존.
- 선택 시: 우측 inspector의 **해당 자산/결과** 제목, 파일 검사와 정량 용도 상태, 허용 행동,
  선택 객체/구역 강조. Inspector는 기본 닫힘이며 비교에서는 자동으로 공간을 독점하지 않는다.
- 접음: 출처 선언·원장·digest·검사 원문·실행/픽셀 설정. 분석 요청은 명시적 행동으로 여는 흐름,
  준비/다운로드는 허용된 보조 행동. 기본 화면의 긴 폼은 아님.
- 자료/결과 전환: left-panel의 탐색 맥락을 바꾸되 중앙은 유지한다. 기존 `/spatial-assets`,
  `/analysis`, `?section=`은 호환 진입점으로 유지할 수 있다. URL 삭제가 목표가 아니다.

### 기본 해부도 (색/스타일 확정안 아님)

| 영역 | 기본 탐색 | 비교 | 결과 확인 |
|---|---|---|---|
| 한 줄 헤더 | 현장·구역 / 단일·비교 / 등록 | 같은 헤더 + A/B 역할 | 같은 헤더, 결과 선택 |
| 왼쪽 탐색 | 관측별 자료·레이어, 자료 찾기 | A/B 선택, 사용 레이어 | 기존 결과 목록, 실제 입력으로 이동 |
| 중앙 | 실제 ortho 또는 DSM 상대 음영, 실제 구역 범위 | 근거가 허용하는 공통 공간 비교; 아니면 독립 보기 | 실제 결과 공간 산출물/영역. 없으면 관련 입력/범위까지만 표시 |
| 오른쪽(선택 시) | 출처·검사·용도 상태 | 각 관측의 정보, 표시 제한 | 계산값·단위·조건·검토(실제 허용 기록만) |
| 시간 선택 | 확인된 관측만 선택, 날짜 정밀도 유지 | A/B를 각각 바꿈 | 결과의 고정 입력 관측 표시, 임의 변경 금지 |

관측이 2개뿐일 때는 작고 이산적인 날짜 선택으로 충분하다. 빈 연도 구간을 긴 장식 timeline으로
그리지 않는다. 시각적 날짜 정렬을 넣더라도 날짜 정밀도·미상·동일 날짜 관측을 보존하며 분석의
기준/비교 시간 순서를 대신 판정하지 않는다. 파일 목록은 필요한 사람을 위한 보조 보기로 남긴다.

### 유지해야 하는 흐름과 실패 복구

1. 현장 진입 → 허용된 읽기 가능 관측 선택 → **실제 픽셀** → 시점/레이어 전환.
2. 자료 선택 → 표시 전환, 정보 열기를 요청하면 inspector → 닫으면 같은 위치.
3. 비교 진입 → A/B 명시 선택 → 공통 표시 조건 대조 → swipe 또는 명확한 독립 보기.
4. 결과 선택(웹/API/MCP 출처 무관) → 원래 입력·영역에 결속된 결과 → 근거/검토.
5. 자료 등록 → 파생 산출물/관측 정보 제출 → 상태 확인 → 해당 관측으로 돌아옴.

보존할 state: Site/WorkArea, 정확한 assetRef·submission/revision, 관측 A/B, 표시 레이어,
표시할 수 있는 CRS·범위의 viewport, 선택 결과 ID, inspector 선택. 구역이 바뀌면 범위가
맞지 않는 선택은 조용히 다른 자료로 치환하지 않고 해제/재선택 이유를 알린다.

표시 성공과 분석 적합성은 별개다. 한 레이어 오류가 다른 허용 레이어 탐색을 막지 않는다.
loading/조회 실패/없음 확정/권한 없음/미지원 형식/부분 범위/분석 차단을 구분한다.
