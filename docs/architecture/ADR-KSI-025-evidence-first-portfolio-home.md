# ADR-KSI-025 — 근거 중심 다현장 Home과 최근 업데이트

- 상태: ACCEPTED (2026-08-23, 대표자 확정)
- 관련 요구사항: REQ-UX-101, REQ-COP-101/102
- 관련 불변식: INV-002, INV-040/041, INV-060/061
- 선행 결정: ADR-KSI-022, ADR-KSI-024

## 맥락

Operations Console의 기존 Home은 미조치 이벤트, 진행 중 작업, 처리 상태, 현장 표와
지표를 한 화면에 병렬로 배치했다. 개별 사실은 맞았지만 경영진·다현장 운영 책임자에게
Home이 작업 원장처럼 보였고, 같은 현장이 여러 카드에 반복되어 무엇을 먼저 봐야 하는지
알기 어려웠다. `처리 중`, `자동 진행`, `확인 필요`처럼 현장명·근거·업무 맥락이 빠진
문구는 KSI가 무엇을 판단했는지 설명하지 못했다.

KSI의 AX 가치는 수치를 많이 보여 주는 데 있지 않다. 현장 데이터를 읽어 무엇이
달라졌는지, 왜 살펴봐야 하는지, 어떤 근거가 있고 무엇은 아직 판단할 수 없는지를
제시하고, 사용자를 해당 현장·작업·근거로 연결하는 데 있다. 동시에 Home은 현장 상세의
2D·3D World, 보고서, 조사 이력이나 드론 운영 화면을 복제해서는 안 된다.

## 결정

### D1 — Home은 다현장 포트폴리오의 입구다

- 첫 줄은 `전체 N곳 · 확인 필요 M곳`만 표시한다.
- 본문 첫 영역은 `확인이 필요한 현장`이다. 한 현장에 사건·작업·상태가 여럿이어도
  가장 우선인 한 장만 표시한다.
- 우선순위는 `미조치 사건 → 사람이 판단할 외부 결과 → 사람이 판단할 WorkOrder → 초기/재관측이
  필요한 Site`다. (2026-09-18 개정, 대표자 승인: 외부 결과 결정 대기 추가 — AX-4,
  `docs/superpowers/specs/2026-09-17-ax-product-loop-design.md` §9)
- `사람이 판단할 외부 결과`는 Core가 원장에서 계산한 두 가지뿐이다: 측정에 성공했으나 검토
  영수증이 없는 외부 체적 보고서(검토 대기), 승인 영수증이 없는 재관측 제안(승인 대기).
  브리핑 문장이나 화면 추정으로 대기 여부를 판단하지 않는다.
- 진행 중 처리·동기화·장비 연결 상태는 Home의 독립 카드로 만들지 않는다. 해당 작업과
  운영 지원 화면이 소유한다.

### D2 — 모바일은 한 현장씩 넘겨본다

- 1024px 미만에서는 한 장이 화면 폭을 차지하는 native horizontal scroll-snap
  캐러셀을 사용한다.
- 이전·다음 버튼, 현장명, 현재 번호와 직접 선택 가능한 pagination을 함께 제공한다.
- 자동 넘김은 사용하지 않는다. `prefers-reduced-motion`에서는 부드러운 이동도 끈다.
- 카드 전체를 모달로 만들지 않고 사건·작업·현장 deep link로 이동한다.

### D3 — 이미지는 실제 등록 근거만 쓴다

- Event evidence에 등록된 image artifact의 만료 제한 presigned URL만 Home 미리보기로
  사용할 수 있다.
- 합성 현장 사진, 고정 placeholder URL, 다른 현장의 사진을 production fallback으로
  사용하지 않는다(INV-040/060).
- 증거가 없으면 `근거 이미지 미등록`, 열람 실패면 `근거 이미지를 불러오지 못함`,
  WorkOrder/Site에 Home용 미리보기 연결이 없으면 `연결된 미리보기 없음`으로 구분한다.
- 이미지가 없어도 상태와 원장 사실은 표시하되, 시각 요소로 사실을 대신 꾸미지 않는다.

### D4 — 최근 업데이트는 사용자 의미가 있는 결과만 보여 준다

- 하단 `최근 업데이트`에는 `결과 준비`, `완료된 조사`, `사람이 종료·오탐 처리한 안건`,
  `현재 원장에 등록된 미조치 관측 없음`만 표시한다.
- 장비 연결, 파일 동기화, 처리 시작, adapter receipt 같은 기술 이벤트는 제외한다.
- `미조치 관측 없음`은 현재 KSI 원장의 범위만 뜻한다. 현장 전체의 정상이나 안전을
  의미하거나 보증하는 문구로 바꾸지 않는다.
- 상단 확인 영역에 나온 현장은 하단에 반복하지 않는다.

### D5 — AI 질문은 실제 근거가 준비된 작업에서만 연다

- `REVIEW_READY` WorkOrder는 실제 Copilot 표면으로 deep link할 수 있다.
- Home에 동작하지 않는 범용 AI 채팅이나 자동 결정 버튼을 만들지 않는다.
- Copilot은 근거형 답변과 재관측 초안만 제공하며 승인·Mission 발급·비행 명령을
  수행하지 않는다(INV-061/002).

### D6 — 승인된 Home 시각 구조는 상태가 바뀌어도 유지한다

- Home의 고정 위계는 `포트폴리오 요약 → 큰 시각 캐러셀 → 초기 설정 필요 현장 →
  최근 업데이트`다. 표시할 항목이 없는 구역은 생략할 수 있지만 순서를 뒤집거나 큰
  시각 영역을 텍스트 빈 상태로 축소하지 않는다.
- 미조치 사건·사람 결정 WorkOrder·재관측 필요 Site가 있으면 큰 시각 영역은
  `확인이 필요한 현장` 캐러셀이다.
- 위 운영 안건이 0건이어도 등록 현장이 있으면 같은 크기와 카드 비율의 `최근 현장`
  캐러셀을 유지한다. 최근 Event evidence가 있으면 그 이미지를 사용하고, 없으면
  `최근 관측 이미지 없음`과 원장 한계를 함께 표시한다. 0건을 정상·안전 판정으로
  표현하지 않는다.
- `UNMAPPED` 현장은 상단 시각 영역을 대체하는 텍스트 목록이 아니라 그 아래
  `초기 설정이 필요한 현장` 카드로 분리한다. 같은 현장에 실제 Event·사람 결정
  WorkOrder가 있으면 해당 근거는 상단 우선 카드에서 숨기지 않는다.
- 390/768/1024/1440px 모두 같은 큰 시각 구성을 사용한다. 1024px 이상은 이미지와
  설명을 좌우로 배치하고, 작은 폭은 한 장씩 세로로 읽는다. 자동 재생은 없다.
- 이 위계, 큰 시각 영역, 안건 0건 전환 규칙은 제품책임자의 명시 승인 없이 변경할
  수 없다. 카피 명료화, 접근성, 오류 복구, 실제 근거 연결처럼 구조를 보존하는 개선은
  허용한다. 구조 변경은 ADR 개정, 4개 viewport 기준 이미지, projection·E2E 회귀
  검사를 함께 갱신해야 한다.

### D7 — 2026-10-21 전체 Console 정보구조 개선에 따른 Home 표시 개정

- Human은 현장 진입 이후뿐 아니라 전역 메뉴·Home·현장 목록까지 여전히 개선이 필요하다고
  지적한 뒤 “그렇다면 개선해봅시다”로 전체 정보구조·연결 화면 개선을 승인했다. 기존 큰 기본
  표지와 등록 상태 중심 구성을 진단한 후의 승인이다. 이 항목은 그 UI 범위만 반영하며
  제품 책임·데이터·권한·우선순위 규칙을 개정하지 않는다.
- D6의 **미리보기 유무와 무관한 큰 시각 영역 고정 높이/카드 비율**은 이 작업에서 더 이상
  강제하지 않는다. Home은 `포트폴리오 요약 → 확인할 현장과 실제 다음 행동 → 초기 설정이
  필요한 현장 → 최근 업데이트`의 책임과 사실 우선순위를 유지한다. 확인할 항목이 없을 때는
  실제 조회된 최근 현장으로 진입할 수 있게 하며, 0건을 정상·안전 판정으로 바꾸지 않는다.
- 실제 연결된 허용 이미지가 없으면 큰 장식 표지/빈 사진 칸 대신 현장명·안건·근거 시점·행동을
  콘텐츠 우선으로 보여준다. 알 수 없는 촬영일·정확도·자료 보유를 만들지 않는다. 조회하지 않은
  미리보기의 부재를 등록 자료의 부재라고 표현하지 않는다. D3의 이미지 권리/출처 제한은 유지한다.
- D1의 안건 선정·현장별 중복 방지와 D4의 최근 업데이트 의미·중복 제외를 유지한다.
  Home이 관측 작업 원장, 받은 업무함, 현장 공간뷰를 복제하거나 새 판단 권위를 만들지는 않는다.
- D2의 모바일 수동 탐색·키보드·현재 위치·reduced-motion 원칙을 유지한다. 여러 현장 안건은
  한 번에 이해할 수 있도록 순서를 명확히 하되, 큰 이미지가 없다는 이유로 고정 높이를 채우지 않는다.
- D6의 과거 문구/기준 이미지는 변경 전 증거로 보존한다. 이번 변경은390/768/1024/1440px의
  실제 변경 전/후 화면, 안건 있음/없음·조회 실패의 projection 회귀와 연결 동선 검증을 남긴다.
  기술 검증은 고객 사용성 연구나 운영/정확도 수용이 아니다.

## 구현·수용 기준

- Home은 Site·Event·WorkOrder의 기존 조직 범위 API를 사용하며 새 Business API를
  만들지 않는다.
- 같은 현장은 확인 영역에 한 번만 나오며, 확인 영역의 현장은 최근 업데이트에서
  반복하지 않는다.
- 데이터 일부를 불러오지 못하면 `확인 필요 0곳`으로 낮추지 않고 `—`와 복구 문구를
  표시한다.
- 390/768/1024/1440px에서 수평 오버플로가 없고 모든 버튼·pagination은 키보드와
  coarse pointer에서 사용할 수 있다.
- 운영 안건 0건과 1건 이상에서 큰 시각 영역의 높이·카드 비율·섹션 순서가 유지된다.
- `UNMAPPED` Site fallback은 초기 설정 카드에 나타나며, 실제 Event·WorkOrder는
  Site 상태와 무관하게 상단 우선순위를 유지한다.
- 4개 viewport 기준 이미지와 Home visual-contract 검사가 D6의 무단 구조 변경을
  차단한다.
- 실제 DJI capability와 Field/HIL 등급은 이 화면 변경으로 승격하지 않는다(INV-041).

## Rollback

- Home projection과 표시 컴포넌트만 이전 구현으로 되돌릴 수 있다.
- Site·Event·WorkOrder·Evidence 계약, URL, 원장에는 migration이 없다.
- 증거 미리보기 문제가 생기면 preview resolver만 비활성화하고 텍스트 기반 근거 링크는
  유지할 수 있다.
