# KSI Site Intelligence Platform — 제품 요구사항

## 0. 규범과 적용

이 PRD는 **제품 정체성·고객 약속·수락되는 기능 범위**를 정의한다. 허용 도메인에서 남은 안전·보안 제약은 [도메인 불변식](DOMAIN_INVARIANTS.md), 계산·ingress·현장 경계는 관련 승인 ADR과 계약이 세부 권위를 갖는다. 구현 설명과 현재 진행상태는 소스·테스트·현재 원장에서 확인한다. 승인 조건은 벤더 문서나 구현 코드의 존재만으로 완료 또는 지원을 뜻하지 않으며, 적용 가능한 기준에 별도 수락 증거가 필요하다.

## 1. 제품 정체성 및 범위

KSI Site Intelligence Platform은 **물리적 현장의 관측을 사람·외부 에이전트·소프트웨어·로보틱스가 재사용하는 근거형 Site State와 Change로 바꾸는 기반이다.** 건설·토공 운영이 첫 시장이며, 플랫폼의 배타적 정체성이 아니다.

고객이 촬영 원본과 재구성 실행을 소유하며, KSI는 제출 파생 산출물의 등록·검사·조건별 데이터 제공과 재현 가능한 분석·근거를 제공한다(ADR-KSI-036/038). 주간 같은 WorkArea의 두 시점 상대 지형변화가 첫 분석 사례이고, 시점 간 결과는 각각 입력·권위에 새로 결속한다(ADR-KSI-037).

비행·자율 취득·전술 인지·제어 및 고객 production 재구성은 현 플랫폼 책임 밖이다(ADR-KSI-039). M4D/Terra는 고객 측 capture/reconstruction의 참조 workflow이지 KSI가 운영하거나 인증한 벤더 통합이 아니다. 지원 형식, 장비, 좌표/수직기준 및 분석 claim은 해당 입력 계약·고객 권리·별도 acceptance가 검증한 경우에만 제공되거나 지원된 것으로 말한다.

### 외부 산출물 활용과 기술 채택 경계

- 원본 사진 처리·매핑·재구성 엔진 개발 및 실행은 제외한다. ODM·NodeODM·PIX4Dengine·DJI TerraAPI의 사진측량 처리는 낮은 우선순위의 후속 기능이 아니라 범위 밖이다. 역사적 managed/test profile과 결과는 보존하되 활성 제품 요구나 도입 근거로 삼지 않는다.
- 정상 작동하는 기존 분석 워커·지도·자료 구조를 우선 유지한다. 검증된 라이브러리·CLI로 필요한 부분을 보완하고, 기술 후보 목록은 설치·교체·버전 변경·지원 약속이 아니다. 새 서비스·커넥터 프레임워크·데이터베이스·STAC 같은 표준의 선행 구축을 요구하지 않는다.
- 결과 폴더 자동 인식은 기존 등록·검사 경로를 보조한다. 파일 변경 감지와 주기적 재검색, 쓰기 완료·재시작·중복 처리, 현장·시점·작업구역 귀속을 검증하며 파일명·폴더명만으로 좌표·수직기준·품질을 확정하지 않는다. 자동 감지는 사용자 권한·바이트 검사·용도 적합성 판정을 우회하거나 분석을 자동 승인하지 않는다. 클라우드 산출물 조회는 고객 권리·명시적 연동 수락이 전제이며 로컬 분석의 필수 의존성이 아니다.
- 외부 도구의 통계·정합·오차 계산을 재사용해도 수평·수직 기준, 독립 검사점과 안정 지형 근거, NoData·유효 중첩·경계 픽셀, 굴착·성토 구분과 불확실성의 해석은 KSI가 책임진다. 래스터 값의 합계는 체적이 아니며 단위·픽셀 면적·포함 비율을 함께 검증한다. 실제 변화 구역을 정합 기준으로 삼아 변화량을 제거하지 않았는지 검증한다. 도구 간 결과 일치는 측량·정산·현장 수락을 대신하지 않는다.
- 설계면은 기존 GeoTIFF·지원되는 LandXML/IFC 정규화 경로의 계약을 따른다. DXF 경계 추출을 3차원 설계면 지원으로 간주하지 않으며 잔여 물량·공정률·시공 검증, 점군·3D 및 추가 벤더 API는 별도 요구·입력 근거·수락 없이 확대하지 않는다.

## 현재 검증 가능한 요구사항 범위

제품 요구 ID와 구현·시험의 추적성은 [현재 승인된 REQ traceability](../acceptance/REQUIREMENTS_TRACEABILITY_v3.0.csv)와 각 승인된 acceptance manifest가 소유한다. Current slice의 EXT-VAL-01..08은 [제품 상태](../superpowers/product-state.md), 외부 데이터·동일 Core 계약의 수락은 [플랫폼 P-AC-01..06](../superpowers/plans/2026-09-30-spatial-data-platform-roadmap.md)에서 확인한다. 이 단락에 PRD SDP-REQ 목록을 또 작성하지 않는다.

## 현재 분석·수락 목표

첫 분석 수락은 같은 Site/WorkArea의 반복 두 시점(`t0→t1`, 이후 `t1→t2`) 상대 지형 변화이며, 동일 구역·비교 규칙은 재사용하되 각 쌍의 입력·정책판정·계산 결과를 새로 결속한다(ADR-KSI-037). 데이터 제공과 분석은 이 플랫폼의 두 경로다(ADR-KSI-038). 현재 검증대상 수락은 명명된 EXT-VAL/P-AC manifest를 따른다. 분석 목표는 새 범용 요구사항을 암묵적으로 승인하지 않는다.

### 에이전트 목표와 첫 검증 시나리오 (2026-11-11 사용자 결정)

제품 목표는 업무 완수형 AI다. 에이전트가 자료를 자율 조사하고 필요한 분석을 판단·실행해 근거 있는 업무 결과물까지 완성한다. 탐색·분석·임시 결과는 자율 실행, 정량 결과는 INV-053 검증 조건 충족 시에만 허용, 공식 확정·외부 제출은 사용자 승인 필수다. 첫 검증 시나리오는 2시점 DSM 변화 전수 조사 → 이상 구역 탐색·지도 표시 → 근거 포함 보고서 초안 생성이며, 성공 기준은 절차 미지정 상태에서의 자율 수행·지도와 결과물 반영·미검증 수치 미생성이다. 상세 경계는 [제품 헌법](PRODUCT_CONSTITUTION.md)의 에이전트 목표와 실행 경계를 따른다. 이 결정은 새 에이전트 프레임워크나 사진측량 엔진 도입을 승인하지 않는다.

## 22. 데이터·고객 권리·보존

- 고객 소유 촬영 원본과 KSI 제출 파생 산출물을 구분한다. 외부 첫 출시의 기본 경로는 고객 원본 전체를 요구하지 않으며 별도 승인된 managed/test source-media 경로는 첫 출시와 혼동하지 않는다(ADR-KSI-036 D4–D6).
- 인증 조직·현장·구역 권한, 제공 권리·사용 목적 및 AI/외부 반출 동의·철회를 등록·메타데이터·바이트 접근 모두에 적용한다. 요청 헤더·에이전트 지시·제공자 선언은 권한을 부여하지 않는다(INV-040/050/060/061).
- 등록, 바이트 검사, 용도 적합성, 정량 결과·정확도, 현장·측량·정산 수락은 구별한다. 좌표·수직기준·시점·계보·NoData·독립 checkpoint 근거가 해당 용도를 충족하지 못하면 의존 분석·claim을 막는다(INV-017/018/020/024/051/053). RTK FIX나 처리 성공만으로 정확도 또는 고객 수락을 주장하지 않는다.
- 고객 데이터와 암호화 키를 분리해 격리하고 학습 사용 동의·Dataset 계보·열람·반출을 감사한다. 보존기간·파기 대상·파생 복제본 처리와 삭제 증빙은 승인된 데이터 권리/고객 계약과 확정 ledger를 확인한다. 권리불명 또는 비상용 자료는 상용 학습에 사용하지 않는다(INV-043/060).
- 기록된 결과는 수정 이력 없이 보존하며, 사용 권한 철회는 미래의 새 접근을 제한한다. 접근 만료는 과거 기록을 삭제하는 지시가 아니다.

## 23.1 첫 번째 Vertical

건설·토공을 첫 검증 시장으로 삼는다. 반복관측 분석과 데이터 제공은 승인된 범위별로 별도 수락한다. 새 산업·포맷·벤더·장비·운영지원은 별도 계약과 권리 있는 수락 없이 지원으로 추정하지 않는다. [베타 프로그램](BETA_PROGRAM.md)은 참가자에게 약속한 판정·근거·조건부 결과만 별도로 정의한다.

# 25. 제품·플랫폼 수락

- 첫 분석사례는 API-first WorkArea별 주간 2시점 지형 물량변화 검토(ADR-KSI-037)다. 첫 플랫폼 수락은 같은 자산 기반 분석과 구역 DSM/정사영상 외부 재사용을 함께 검증한다(ADR-KSI-038).
- 승인된 플랫폼 활용의 수락기준 P-AC-01..06과 EXT-VAL-01..08 current slice를 적용한다. 이는 SDP delivery/analysis 또는 EXT-VAL의 상세 체크리스트를 이 문서에 다시 전사하지 않는다.
- 비행·자율 취득·전술 제어·고객 production 재구성은 ADR-KSI-039에 따라 현 플랫폼 출시 완료조건이 아니다. 데이터 접근·계산·결과 내보내기는 해당 권리·계약이 현재 승인한 범위만 지원으로 표시한다.

# 26. 제품 완료와 미수락 조건

제품 완료는 [현재 slice와 P-AC](../superpowers/product-state.md), 현행 계약·도메인 불변식 및 독립적인 host/customer acceptance 증거로 판단한다. 구현이나 로컬 테스트만으로 현장·고객 출시를 주장하지 않는다.

- 자료 등록·형식 및 메타데이터 검사·목적별 적합성·수치 결과·사람 검토·재관측은 각각 구분한다. 한 층의 성공은 다른 층을 승격하지 않는다.
- 정확도·측량·정산·공정·품질 승인은 별도 명시 수락과 고객이 허용한 실제 근거가 있을 때만 제시한다. 상대 물량, RTK FIX, checkpoint 소프트웨어 검증은 이를 단독으로 입증하지 않는다.
- 제품 지원·가격·SLA·보존 또는 삭제 의무는 명시 승인/계약과 검증 없이 확정하지 않는다. 구현·스키마에 없는 벤더/포맷/엔진 통합을 시험이나 문서에 의해 약속하지 않는다.
- 결과 및 역사 근거는 승인된 변경·삭제 정책을 따른다. 테스트 기록이 불변 결과에 대한 보존 근거를 만들지 않는다.

## 구현·시험 상세의 현재 소유자

UI 카피·렌더 동작과 라우트 안내는 Console source/test 및 [`CONSOLE_CURRENT_SPEC`](../design/CONSOLE_CURRENT_SPEC.md)이, 현행 API·계약검증은 contracts와 각 owner test가, 개발 도구 실행은 package/pyproject/CI entrypoint가 각각 소유한다. 세부 모듈 설명, CLI 옵션, 옛 REQ ID 부록, 실측 로깅, 칼리브레이션 값·Edge 경로는 개별 실행 코드·계약·HIL에서 확인한다. 이 문서의 부재한 phase나 ID를 완료, 활성권한 또는 출시 수락으로 해석하지 않는다.
