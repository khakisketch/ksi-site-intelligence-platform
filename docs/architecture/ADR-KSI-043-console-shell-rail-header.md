# ADR-KSI-043 — 콘솔 셸: 헤더·접이식 레일·3단 탐색

- Status: Accepted
- Date: 2026-11-15
- Supersedes: ADR-KSI-042의 메뉴 배치(공간·분석 두 항목, 좌측 사이드바의 현장 전환·사용자 블록, 모바일 하단 4탭). 공간·분석의 주소와 책임 구분은 042를 따른다.

## 맥락

사이드바 안에 현장 전환·검색·사용자 블록·메뉴가 함께 있어 좁은 폭에서 어색했고, 공간 안에 메뉴가 늘어나면 둘 곳이 없었다. 주 사용 주체는 에이전트이며 화면을 보는 사람은 IT에 익숙하지 않은 현장 담당이다. 시안 비교(A–D) 끝에 D안을 택했다.

## 결정

**셸**: 상단 헤더 한 줄(로고=홈 · 프로젝트 전환 · 프로젝트 설정 · 검색 ⌘K) 아래에 접이식 아이콘 레일과 본문을 둔다. 레일은 펼침 188px, 접힘 56px이며 접으면 아이콘 옆에 이름이 뜬다. 접힘은 사용자가 고른 값만 기억하고(`ksi.console.desktop-nav.v1`) 서버 렌더는 항상 펼침이다. 이 사용자 선택은 1024px 이상에만 적용한다. `/login`은 셸을 쓰지 않는다.

**계정과 페이지 이름**: 768px 이상에서 계정 메뉴는 레일 맨 아래에 둔다(펼침은 이니셜+이름·역할, 접힘은 이니셜). 현재 어느 섹션인지는 레일의 선택 표시가 알려 주므로 헤더는 페이지 이름을 되풀이하지 않는다. 768px 미만은 레일이 없어 헤더가 페이지 이름과 계정 버튼을 가진다. 프로젝트 설정 화면은 설정 아이콘이 현재 위치로 표시된다.

**3단 탐색** — 트리 안의 트리를 만들지 않는다.

| 단 | 위치 | 담는 것 |
|---|---|---|
| 1 | 레일 | 프로젝트 안: 공간·자료·분석. 어디서나: 작업·도움말. 프로젝트 밖: 홈·프로젝트 |
| 2 | 섹션 안 컨텍스트 패널의 탭 | 그 섹션의 보기(레이어·구역·시점, 분석 유형 등) |
| 3 | 우측 Inspector | 선택한 항목의 상세 |

새 기능은 레일 항목 / 컨텍스트 탭 / Inspector 탭 / 헤더 ⋯·설정 중 하나로만 들어간다. 레일 항목이 6개를 넘기면 "더보기"로 접는다.

**프로젝트 전환**은 헤더에서 한다. 목록은 레이아웃이 내려준 접근 가능한 프로젝트뿐이며(새 조회·권한 없음), 고르면 보던 섹션을 유지한다. 현재 프로젝트는 URL에서만 정한다.

**섹션 해석**(`resolveProjectSection`): 프로젝트 루트는 공간, `/data`와 `?panel=materials|intake`는 자료, `/analysis`·`/observations…`·`?mode=results`는 분석. 설정(`?section=manage`)은 어느 섹션도 현재로 표시하지 않는다.

**크기 구간**: 768px 미만은 하단 탭, 768–1023px는 항상 접힌 레일(56px, 접기 버튼 없음)과 헤더 한 줄, 1024px 이상은 위 규칙이다. 브라우저를 125~200% 확대해 CSS 폭이 줄어도 레일이 유지되도록 셸 기준을 768px로 둔다(본문 안의 `lg` 기준은 그대로). 768px 이상의 공간 화면은 현장 머리말을 접어 지도에 세로 공간을 준다. 터치 기기의 레일 항목은 44px 이상이다. 2200px 이상은 글자 배율(`--ui-scale` 1.125, 3000px 이상 1.25)과 본문 컬럼 폭을 키운다(간격·레일 폭은 그대로).

**모바일**: 하단 탭은 프로젝트 안에서 공간·자료·분석·작업, 밖에서 홈·프로젝트·작업·계정. 계정은 헤더 메뉴가 맡는다. 좁은 화면의 하단 시트는 헤더 위를 덮는다(헤더는 lg 이상에서만 상위 층).

**용어**: 새 셸(헤더·레일·전환 메뉴)에서만 "프로젝트"를 쓴다. 본문의 현장·작업구역은 화면별로 바꾼다. 절토·성토 같은 건설 용어는 변화 분석 결과 안에만 둔다. 라우트(`/sites`, `work-areas`)와 API는 바꾸지 않는다.

## 자료 섹션과 섹션 틀 (2단계)

자료는 독립 화면 `/sites/{id}/data`다. 공통 틀 `SectionFrame`이 컨텍스트 패널(구역 선택·검색·필터) · 본문(자료 표) · 오른쪽 Inspector(선택한 자료 상세) · 하단 서랍(등록 진행)을 맡는다. 1280px 이상에서는 세 열이 각자 스크롤하고, 그보다 좁으면 본문 → 상세 → 서랍 순으로 쌓는다. 자료 조회가 구역 단위라 구역 선택이 컨텍스트 패널의 첫 줄이며, 프로젝트 전체를 한 표로 합치는 것은 후속이다.

표의 열은 자료·취득 시점·좌표 기준(파일에서 관측한 값)·파일 검사다. 분석 적합성은 이 목록에서 평가하지 않으므로 열로 두지 않고 "분석 사용 여부는 분석의 실행 전 점검에서 확인합니다"라고만 말한다. 읽기(구역별 자료 목록, 단건, 등록 이력, 작업 목록)와 권한은 공간 뷰어의 자료 패널이 쓰던 것과 같다.

옛 주소는 계속 받는다: `?section=materials|assets|spatial-assets`와 `/spatial-assets`(A/B 시각 쌍이 없을 때)는 `/data`로, `?section=work-orders`와 `/progress`는 `/data?progress=1`(서랍 열림)로 보낸다. A/B 쌍 요청은 기존대로 공간 비교로 간다. 공간 뷰어 안의 자료 패널(`?panel=materials`)은 뷰어에서 볼 관측을 고르는 보조 패널로 남는다.

## 분석 섹션 (3단계)

분석도 `SectionFrame` 위에 놓는다. 컨텍스트 패널은 분석 종류(변화 분석·외부 비교)와, 탐색하던 구역·자료 맥락을 그대로 들고 공간으로 돌아가는 링크다. 본문은 이력(최근 요약과 줄마다 실행·적합성 상태)이고, 줄을 고르면 그 분석의 상세(확인 및 보완·계산 결과·산출물·결과 검토·근거·결과 재사용)가 오른쪽 Inspector에 나온다. 1280px 미만에서는 상세가 이력 아래로 가며, 줄을 고르면 상세로 스크롤한다. 새 분석 요청 화면에서는 Inspector가 "선택한 쌍의 분석 조건 확인"을 맡는다(버튼은 모두 `type="button"`이라 양식 밖에서도 요청을 제출하지 않는다). 외부 비교는 목록뿐이라 Inspector 없이 컨텍스트 패널과 본문만 둔다(`SectionFrame`의 `inspector`는 선택 사항).

이 단계는 화면 배치만 옮겼다. 읽기·권한·판정·요청 상태 관리는 `AnalysisRequestPanel` 안에 그대로 있고, 이력 줄(`AnalysisCard`)과 상세(`AnalysisDetail`)로만 나눴다. 선택하지 않은 줄에는 요약 수치만 남고, 상세를 읽지 못한 선택 줄에는 수치를 보이지 않는다. 현장 머리말(`SiteHeader`)과 `AnalysisTabs`는 분석 화면에서 걷었다(현장 이름·전환은 셸 헤더가 맡는다). 분석 하단 서랍(이력)은 이력이 본문이라 두지 않았다.

## 화면 폭과 컨트롤 모양 규칙

- **폭**: 홈·프로젝트 목록·작업 같은 목록 화면도 공간·자료·분석처럼 가용 폭을 그대로 쓴다(`.console-page`의 최대 폭 제한을 걷었다). 와이드 모니터에서 화면마다 폭이 달라지지 않게 하려는 것이다. 카드 격자는 열 수를 고정하지 않고 `auto-fill`로 폭을 채운다. 읽는 글이나 양식은 각자 `max-w`로 줄인다(양식 `!max-w-[800px]` 등, 설명 문단 `max-w-3xl`).
- **컨트롤 모양**: 비슷한 일을 하는 컨트롤은 같은 모양으로, 다른 일은 다르게 보이게 한다. 보기 전환(카드|목록)은 아이콘이 있는 분할 토글(고른 쪽이 떠 있음), 상태 필터(전체·등록됨 …)는 고른 쪽이 짙게 채워진 알약과 건수 배지(`.console-filter-link`), 한 화면 안의 보기 전환(받은 작업|전체 작업, 분석 종류)은 밑줄 탭, 실행은 버튼이다.
- **헤더 로고 칸**: 레일 폭(펼침 188px·접힘 56px)과 같고 접으면 아이콘만 남는다.
- **레일**: 프로젝트 안에서도 홈·프로젝트를 위에 두고 그 아래에 "현재 프로젝트"(공간·자료·분석)를 둔다. 프로젝트 아이콘(타일)과 공간 아이콘(지도)은 구분한다.

## 이번 단계에서 하지 않은 것

공간의 컨텍스트 탭·시점 타임라인, 명령 팔레트의 자료 섹션 항목, 변화량(깎임·쌓임) 지도 경로는 후속 단계다. 공간 화면에는 현장 머리말의 공간·분석 탭이 좁은 화면에 남아 있어 하단 탭과 겹치며 후속에서 정리한다.

Core 권한·검증·분석 계약과 결과의 수락 범위는 바뀌지 않는다.
