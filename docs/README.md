# Documentation map

Start with `00_READ_FIRST.md`. Use `DOCUMENT_STATUS.md` to distinguish active authority/current state
from historical, superseded, audit, and archived material.

| Path | Responsibility |
|---|---|
| `product/` | Constitution, durable decision ledger, PRD, and domain invariants |
| `architecture/` | Accepted architecture decisions and detailed control/source boundaries |
| `acceptance/` | Acceptance criteria and traceability |
| `goals/` | Current phase registry plus historical execution plans/handoffs |
| `hil/` | HIL/field readiness, evidence, and operator routing |
| `ops/`, `security/`, `dji/` | Operations, security, and provider-specific guidance |
| `audit/` | Dated evidence/findings; not product authority |
| `archive/` | Superseded/non-authoritative material retained for provenance |
| `design/` | Historical implementation-design contracts, not visual design assets |

Repository code ownership and runtime boundaries are in `../REPOSITORY_STRUCTURE.md`.
