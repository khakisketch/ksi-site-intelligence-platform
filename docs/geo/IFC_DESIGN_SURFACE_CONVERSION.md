# IFC 설계모델 → 설계 기준면 GeoTIFF 변환

> IFC는 계속 `tools/convert_ifc_design_surface.py` 로 높이 GeoTIFF를 만들어 설계면
> 등록 경로에 올릴 수 있다. ADR-KSI-030의 v1 확장으로 GeoTIFF 직접 등록과 LandXML
> TIN Surface ingress가 함께 지원되며, LandXML은 원본 bytes·selector·정규화 계보를
> 보존한다. 이 IFC 경로도 같은 결정론적 TIN rasterization 규칙을 사용한다. 계약과
> 실제 파서의 지원범위가 이 안내보다 우선한다.

## 사용법

```bash
uv run python tools/convert_ifc_design_surface.py \
    --input 설계모델.ifc --output 설계면.tif --cell-size 0.5
```

성공하면 산출 GeoTIFF 를 대시보드의 설계 기준면 등록 화면(현장 → 설계)에서
일반 GeoTIFF 와 똑같이 올린다. 변환은 결정적이라(같은 입력 → 같은 바이트) 등록
경로의 해시 대조가 그대로 성립한다.

## 도구가 거부하는 입력 — 거부는 정상 동작이다

| 입력 | 왜 거부하나 | 조치 |
|---|---|---|
| georeferencing 없는 IFC | 로컬 좌표를 세계좌표처럼 실을 수 없다 — 조용히 진행하면 엉뚱한 위치의 설계면이 된다 | 설계 소프트웨어에서 좌표 기준(georeferencing, IFC4 의 IfcMapConversion)을 넣어 재내보내기 |
| IFC2X3 | 좌표 기준을 담는 방식 자체가 달라(별도 pset) 아직 지원하지 않는다 | IFC4 이상으로 내보내기 |
| EPSG 코드를 읽을 수 없음 | 좌표계를 지어내지 않는다 | `--crs EPSG:xxxx` 로 명시(파일 값과 다르면 그것도 거부) |

## 셀 크기(--cell-size) 선택

- **기본 0.5m 로 시작한다.** 잔량 계산은 설계면을 현재 지형(드론 DSM) 격자로
  재표본하므로 설계면이 cm 급일 필요가 없다 — 계획면은 구간별 평면이라 0.5m 면
  경사 변화선 부근 말고는 손실이 없다.
- 경사 변화(법면 어깨·소단)가 조밀한 설계면 폭보다 셀이 크면 그 부근이 뭉개진다
  — 가장 좁은 소단 폭의 절반 이하로 줄인다.
- 셀을 줄이면 파일과 메모리가 제곱으로 는다(도구가 5천만 셀에서 거부한다).
  변환 후 출력의 "값 있는 셀" 비율과 계획고 범위가 설계와 맞는지 확인하라.

## 높이 기준(수직기준) — 파일로는 알 수 없다, 등록할 때 선언한다

IFC 도 GeoTIFF 도 높이가 타원체 기준인지 해발(표고)인지 신뢰성 있게 담지
않는다(이 저장소의 확립된 사실 — 설계면 계약의 `verticalReference` 가 선언
전용인 이유). **이 도구는 IFC 의 높이값을 그대로 옮길 뿐이다.** 등록 화면에서
이 도면의 높이 기준을 근거와 함께 선언하라 — 해발(표고)로 선언하면 잔량 계산이
국가 지오이드 모델(KNGeoid24) 격자로 드론 측량과 같은 기준으로 자동 정합한다
(2026-08-12 도입, `GEOID_ACQUISITION.md`). 기준을 잘못 선언하면 한국에서
20~30m 가 조용히 잔량에 들어간다 — 도구도 서버도 그 거짓말은 잡지 못한다.

## 알아두고 쓸 것 (도구 docstring 요약)

- **상단 표면(top surface)**: 셀값 = 그 셀에 떨어진 설계 표면 표본의 최대 z.
  위에서 본 표면이라는 뜻이고, 교량 하부처럼 면이 위아래로 겹치는 구조는 위쪽만
  남는다.
- **설계 범위 밖 셀은 빈 값(NaN)** 으로 남고 보간으로 메우지 않는다 — 잔량
  계산은 그 셀을 "모름"으로 집계에서 제외한다.
