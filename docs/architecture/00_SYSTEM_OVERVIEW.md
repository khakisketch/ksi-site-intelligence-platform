# KSI Site Intelligence — 시스템 전체 구성 (한 장 개요)

> 2026-08-14 대표자 확정. 이 문서는 **목표 구성도**와 **현재 도달점**을 한 장에
> 담는다 — 둘을 섞어 말하지 않는다(green≠작동 원칙). 개별 결정의 근거는 각 ADR이
> 정본이고, 이 문서는 그 결정들이 모여 만드는 전체 그림이다.

## 한 문장 정의

**Matrice 4D와 Manifold 3가 현장을 반복 관측하고, KSI Server가 그 데이터를
시간축 공간정보로 만들어 변화·진척을 판단한 뒤, 필요한 영역을 다시 관측시키는
자율 현장 데이터 수집·분석 시스템.**

## 전체 구성도 (목표)

```text
                        건 설 현 장
        ┌──────────────────────────────────────┐
        │  Matrice 4D        실제 비행·촬영·RTK │
        │      │ E-Port / PSDK                  │
        │  Manifold 3        KSI Edge SW        │
        │   · 임무 계약 수신·검증 (서명·TTL)     │
        │   · 관측 품질·누락·재관측 판단          │
        │   · 통신두절 시 로컬 지속(저장후전달)   │
        └──────┬───────────────────────────────┘
               │ DJI 기체↔RC 무선 링크
        ┌──────▼───────────────────────────────┐

        │   · 조종자 비행 운용(이륙 승인은 사람) │

        └──────┬───────────────────────────────┘
               │ MQTT / HTTPS / WebSocket
        ┌──────▼───────────────────────────────┐
        │  KSI SERVER                           │

        └──────┬───────────────────────────────┘
               │ 다음 임무 (서명된 계약 + 경로)
```

## 핵심 설계 원칙 — 폐루프는 두 개다

하나의 중앙제어 시스템으로 만들지 않는다. 시간축이 다른 두 지능을 분리한다.

**① 기체 안의 빠른 폐루프 (Manifold 3, 수초 단위)**
"사진이 흔들렸다 / A구역이 가려졌다 / 각도가 안 맞다 → 옆으로 이동해 다시 보자."
이 판단을 서버까지 보내 답을 기다리지 않는다 — Manifold이 처리하고, 통신이
끊겨도 이 루프는 계속 돈다. (근거: CLAUDE.md Control boundaries,
`01_ARCHITECTURE_AND_CONTROL`, ADR-KSI-005 결정 3)

**② 서버의 큰 폐루프 (KSI Server, 비행·일 단위)**
"어제와 비교하니 A구역이 이상하다 / B구역 토공량 확인 필요 / C구역 데이터 부족
→ 다음 비행에서 여길 보자." 여러 비행·여러 날짜를 비교하는 긴 시간축 판단이다.

## 데이터 경로 — 실시간과 대용량을 나눈다 (ADR-KSI-005 결정 2)

| 데이터 | 경로 | 방식 |
|---|---|---|
| 작은 실시간(상태·관측품질·AI 결과·재관측 신호) | Manifold → 기체 링크 → Pilot 2 → 서버 (PSDK Pilot Cloud WebSocket) | 비행 중 전송 |
| 대용량 원본(사진·영상·raw·로그) | Manifold 로컬 저장 → 연결 여건이 좋을 때 Object Storage | **store-and-forward** — 네트워크 때문에 수집이 실패하지 않는다 |

## MSDK의 위치 (ADR-KSI-017)

기본 제품 경로는 `M4D → Manifold 3 → Pilot 2 → KSI Server`이며 MSDK는 없다.
MSDK는 **서버→Manifold 양방향 제어가 Pilot Cloud만으로 해결되지 않을 때 추가하는
옵션 계층**(MOP 경유)이다 — 지우지도, 핵심 경로로 만들지도 않는다.

## 책임 분담

| 구성 | 책임 |
|---|---|
| Matrice 4D | 움직이고 촬영 (저수준 비행·회피·RTH는 DJI FC 소유) |
| Manifold 3 | 현장에서 보고 판단 (빠른 폐루프) |
| RC Plus 2 + Pilot 2 | 사람이 운용하고 지상과 연결 (이륙 승인은 항상 사람) |
| KSI Core | 현장·임무·서명 계약·권한·감사 |
| Spatial Processing | 사진 → 공간정보 (NodeODM 재구성) |
| KSI Intelligence | 무엇이 달라졌는지 판단 (변화·토공량·공정률·이상영역) |
| Planner | 어디를 다시 볼지 결정 → 다음 임무 |
| Dashboard | 사람이 전체 현장을 이해하고 승인 |

## 현재 도달점 (2026-08-14 실측 — 목표와 구분해 적는다)

| 구성요소 | 상태 |
|---|---|
| ① CORE | **가동** — 현장·임무·계약·권한·이벤트 전부 구현·검증 |
| ② SPATIAL | **가동** — 업로드→재구성→정사영상·DSM·토공량 종단 완주 (단, 입구가 수동 사진 업로드) |
| ③ INTELLIGENCE | **가동** — 변화탐지·설계대비·공정률 계산 완성 |
| ④ PLANNER | **조각 존재** — 변화영역 추출·재관찰 초안·경로 생성이 각각 있으나 하나로 이어진 화면 없음 (P3 과제) |
| Manifold 3 Edge SW | **소프트웨어 검증 완료, 실기 0회** — DPK 설치·기동을 실기에서 시도한 적 없음 (P0 과제) |
| RC 게이트웨이 (dji-gateway) | **빈 골격** — MQTT/WebSocket 수신부 미구현, M4D의 Pilot Cloud 지원 자체가 미확정 |
| 드론→서버 자동 ingest | **없음** — 사람이 사진을 손으로 올린다 (P1 과제) |
| 폐루프 종단 완주 | **0회** — 목표 원장 `autonomous-acquisition-closed-loop` (strict) |

우선순위는 P0(Manifold HIL) → P1(자동 ingest) → P2(분석→재관측 폐루프) →
P3(지도 하나 UI)다. 상세는 ADR-KSI-018과 목표 원장 참조.

## 관측 자율성 3단계 (ADR-KSI-019)

위 "④ PLANNER" 행을 성숙도 축으로 분해한 것이다 — PRD §25의 Phase 번호와 **다른
축**이므로 `AOL-` 접두사를 쓴다.

| 단계 | 내용 | 현재 |
|---|---|---|
| AOL-1 매핑 자율 | 경계 → 매핑 경로 → 승인 → 실행 → 촬영 → 재구성 → 공간모델 등록 | 경로·계약 발급은 **가동**, 실행·촬영 회수·모델 등록 자동화가 GAP |
| AOL-2 분석 기반 재관측 | 공간모델+분석 → 대상 영역 → 재관측 경로 → 승인 → 재촬영 → 모델 갱신 | 변화영역 → AOI 초안 → KMZ 발급까지 **가동**(소프트웨어), 밀도 조정은 GAP |
| AOL-3 공간모델 인지 비행 | DSM/Point Cloud 를 경로계획 입력으로(지형추종·이격·장애물·적응촬영) | **미착수** — AOL-1보다 먼저 하지 않는다 |

반순환 불변식(ADR-KSI-019 D3): **최초 매핑 임무는 공간모델 없이 생성 가능해야
한다** — 경로 생성기에 공간모델을 필수 입력으로 넣는 변경은 금지다.
