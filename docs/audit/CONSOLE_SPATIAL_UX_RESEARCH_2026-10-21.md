# KSI Console 공간 작업공간 — UI·UX 조사와 개선 우선순위

- 조사일: 2026-10-21
- 상태: **조사 결과·설계 가설. 구현 명세/승인된 새 제품 계약/고객 사용성 수용 아님.**
- Human 요청: 경쟁 공간정보 도구에 익숙한 경험을 원하며, 후속으로 “UI UX 조사 등 체계적으로”.
- 대상: 실제 Console frontend `35d2ded0`, Git `3f60abe7`(문서만 후속 변경), 개발 OIDC와 저장된 자료.
- 범위: 현장 선택 → 관측/레이어 탐색 → 비교 또는 제한 이해 → 결과/근거/검토 → 자료 재사용 진입.
- 이번 산출물: 현재 경험 진단, 공식 경쟁 자료 대조, 개선안의 선택 근거, 검증 과제. **제품 코드는 변경하지 않았다.**

## 1. 조사 질문과 성공의 정의

질문은 “경쟁사와 비슷하게 보이는가?”가 아니라 다음 다섯 가지다.

1. 처음 보는 사람이 어디를 보고 있고, 어떤 자료인지 알아보는가?
2. 같은 구역에서 날짜·레이어를 바꾸고 원래 보던 자료로 돌아갈 수 있는가?
3. 단순 열람과 정합 비교·수치 계산을 구별하는가?
4. 수치의 입력·제한·검토를 확인하고 정확한 과거 기록을 다시 찾는가?
5. 자기 권한/기기에서 불가능한 작업의 이유와 가능한 다음 행동을 찾는가?

비용이 큰 실패: 다른 구역/보정본을 같은 입력으로 오인, 열람 성공을 정량 적합성으로 오인,
합성 수치를 실제 해안 관측에 귀속, 검토 기록을 공식 승인으로 오인, 화면 이동을 계산 구역
수정으로 오인, 잘못된 계정의 표시 출력 접근. 화면 유사성이나 클릭 수보다 먼저 방지한다.

### 권위와 보존할 제약

Read First → Constitution → Decision Ledger → PRD §1.1–1.1.2, ADR-036/037/038/039,
현장 작업공간 UX 계약을 기준으로 했다. 현행 전역 Home/Sites/Work와 현장 소유권은 유지한다.
하위 정보구조 개선 제안이 수용된 영역·권한·경로 삭제를 자동 승인하지 않는다.

- KSI는 외부 산출물 수용·데이터 활용·근거형 분석 플랫폼이지 촬영/재구성 도구의 대체제가 아니다.
- 날짜만 아는 관측은 날짜만 표시한다. 등록일을 촬영일로 바꾸지 않는다.
- 관측, 제출 묶음 revision, 원본 자산, 표시 파생물, 분석 입력은 구분한다.
- 등록·검사·용도별 적합성·계산·정확도·사람 검토·감사 무결성을 통합 READY로 만들지 않는다.
- 표시 범위는 WorkArea 계산 다각형이 아니다. 서버 근거 없는 정합/동기 비교를 만들지 않는다.
- 현재 접근권·요청자 소유권·바이트 크기/SHA 검사를 유지하며 진입/탐색으로 PREPARE·분석 POST를 하지 않는다.
- 1024px 미만 쓰기 제한, AI 반출 별도 동의, 공유 감사 원장 보호는 변하지 않는다.

관련 불변식: INV-020(좌표/범위 의미), 024(정확도 신호와 검증 구분), 040(실제 사실),
051(원본/파생 권위), 053(비교 조건), 060/061(범위·권한·반출). 이번에는 설계 제약으로 대조했으며
새 강제 지점/스키마를 추가하지 않았다.

## 2. 방법과 증거 수준

| 방법 | 수행 범위 | 주장할 수 없는 것 |
|---|---|---|
| 과업 기반 전문가 walkthrough | 실제 1440×1000, 390×844; 현장 진입·이동/확대·비교 복귀·자료 목록 진입 | 처음 쓰는 고객의 성공률·만족도 |
| 현재 화면 직접 판독 | Home/Sites/Explore/Compare/Results/Materials; 모바일·준비 중·완료 상태 | 캡처하지 않은 모든 상태의 품질 |
| 기존 유효 증거 재사용 | 같은 build의 날짜/DSM/Back/reload/권한/결과→근거→저장 검토 | 재현 계산·실기기 touch·SR 수용 |
| 독립 검토 | 별도 fresh-context 세션에서 현재 원본 화면과 관련 소스 검토 | 독립 참여자 연구나 고객 인터뷰 |
| 경쟁 데스크 리서치 | DroneDeploy·Propeller 공식 지원 문서와 원본 UI 이미지 직접 판독 | 로그인한 제품의 직접 조작·성능·고객 선호 |
| 접근성 기초 점검 | 설치된 axe-core의 WCAG 2/2.1 A·AA 태그, Explore desktop·Results mobile | WCAG 전체 적합성, 인지 접근성·SR·touch 검증 |

**증거 분류:** O=실제 관찰, D=공식 문서 설명, H=아직 검증하지 않은 사용자/설계 가설.
P1=핵심 과업/오해 위험에 먼저 대응, P2=주변 동선·명료성 보완. 점수 합산이나 ROI 숫자를
만들지 않았다. P0급 권한·수치 계약 위반이 이번 조사로 확인된 것은 아니다.

대표 사용자 가설은 ①반복 관측을 다루는 디지털/현장 운영자 ②결과를 판단하는 검토자
③모바일 읽기 사용자 ④자료를 재사용하는 통합 개발자다. 우선 고객은 제품 문서의 가설이며,
실제 고객 인터뷰·참여자는 **0명**이다. 넷을 한 화면에 모두 상시 노출해야 한다는 뜻은 아니다.

## 5. 우선순위: 관찰 → 영향 → 제안 → 확인 방법

### F1 · P1 — 겹치는 길 찾기와 중간 진입 화면

- **O:** 현장에 `현황·자료·분석·검토·작업·관리`와 `탐색·비교·결과`가 동시에 나타남.
  자료 메뉴에는 실제 목록 이전에 설명/`자료 열기` 화면이 한 번 더 있음(K1/K2).
- **H/영향:** 처음 온 사람은 영상 탐색을 ‘자료’에서, 결과를 ‘분석·검토’에서 찾아 돌아갈 수 있음.
  실제 혼동 빈도는 아직 모름. 버튼 수 자체가 결함이라는 판단은 하지 않음.
- **제안:** 현장의 권한·소유 경로를 보존하고, 일상적인 공간 작업의 주 내비게이션과 등록/관리의
  보조 내비게이션을 시각적으로 분리. ‘자료’ 진입은 같은 범위의 실제 목록/패널을 직접 여는 안을 비교.
- **trade-off:** 작업공간 전환은 학습 비용을 줄일 가능성이 있지만 기존 사용자 경로를 바꿈.
  accepted area/route 삭제는 제안하지 않음. 기존 링크·deep link·뒤로가기를 유지해야 함.
- **검증:** 첫 클릭 테스트에서 ‘다른 촬영일 보기/기존 결과 근거 찾기’의 목적지 선택과 되돌아감 관찰.

### F2 · P1 — 지도처럼 보이지만 버튼 중심인 조작, 모바일 조작 위치

- **O:** T3에서 드래그·휠은 표시 격자를 바꾸지 않고, 버튼 확대/복귀는 작동. 모바일 버튼은
  y813.5/865.5로 이미지와 떨어져 첫 화면 밖에 있음. 44px 버튼 크기는 확보되어 있음(K2/K4).
- **H/영향:** 공간정보 도구 경험자는 먼저 drag/wheel을 시도하고 반응이 없어 멈춘 것으로 볼 수 있음.
  경쟁 화면 캡처만으로 각 제품의 gesture 구현을 추정하지 않음.
- **제안:** 주 조작을 canvas 가장자리의 일관된 위치에 두고 키보드 대안을 유지.
  drag/wheel/touch는 실제 구현·권한·출력 범위가 받쳐 줄 때 지원하며, 없는 gesture를 안내문에 쓰지 않음.
- **trade-off:** overlay는 픽셀을 가리므로 작게/접을 수 있게 하며 모바일 고정 내비게이션과 겹치지 않음.
  모든 pan/zoom을 새 준비 작업으로 연결하면 안 됨. 표시 이동은 계산 구역 편집과 명백히 달라야 함.
- **검증:** pointer drag, wheel, 버튼, keyboard, 복귀, 경계/부분 출력에서 동작을 각각 확인;
  gesture 지원 시 write 0, exact source와 WorkArea 불변을 함께 확인. 물리 touch는 별도 검사.

### F3 · P1 — ‘비교’가 뜻하는 작업과 가능한 다음 행동

- **O:** 날짜-only Floreat에는 비교 후보가 없지만 ‘두 지도는 같은 크기’, ‘이 구역 변화 비교’,
  ‘구역 자료 준비’ 안내가 남아 있음. 복귀 링크 자체는 정확한 범위를 유지함(K2/K5).
- **H/영향:** 사용자가 단순히 두 날짜를 보고 싶은 것인지 수치를 계산하려는 것인지 결정하지
  못하거나, 준비를 더 하면 시간/정합 조건도 해결된다고 오해할 수 있음.
- **제안:** ‘다른 관측 열람’, 근거 있는 ‘정합 비교’, ‘변화량 분석’을 목적과 조건으로 구분.
  현재 불가능한 작업은 그 이유와 실제 가능한 복귀를 먼저, 아직 선택하지 않은 비교의 설명은 후순위.
- **trade-off:** 이름을 나누면 메뉴가 늘 수 있음. 최상위 항목을 세 개 더 만드는 대신 맥락 안에서 구분.
  날짜-only/정합 NONE을 우회해 독립 열람을 정합된 쌍이나 수치 비교라고 부르지 않음.
- **검증:** 사용자가 제한 이유를 설명하고, 가능한 열람으로 돌아가며, 새 준비가 해결하지 못하는
  조건을 구별하는지 확인. 테스트를 위해 Floreat을 임의 정량 적격 자료로 바꾸지 않음.

### F4 · P2 — ‘준비 중’은 서버 작업인가, 이미 있는 자료를 읽는 중인가

- **O:** 초기 K1 Explore는 기존 준비 출력의 GET/해독 중인데 타일에 ‘준비 중’, 하단에
  ‘나머지는 준비 중’이 보임. 이후 K2에서 4/4로 그려짐. POST/신규 작업은 없었음.
- **H/영향:** 사용자는 연산을 새로 시작했거나 일부 자료가 없다고 해석할 수 있음.
- **제안:** 읽는 중 / 표시 준비가 필요한 범위 / 접근 불가 / 읽기 실패를 실제 상태에 따라 구별.
  현재 단계와 재시도/취소가 의미 있는 경우만 그 행동을 제공. 처리 성공을 정확도 성공으로 쓰지 않음.
- **trade-off:** 상태를 모두 상시 badge로 펼치면 원래의 진단 벽으로 돌아감. 화면에는 현 상태와
  행동만, 요청·검사 상세는 disclosure에 둠. byte identity와 접근 검사 자체는 줄이지 않음.
- **검증:** 기존 출력 GET loading과 진짜 미준비/실패/회수 상태를 각각 테스트. 현재 측정을
  ‘cold 23초→개선’ 같은 성능 주장으로 바꾸지 않음.

### F5 · P2 — 촬영일과 보정 버전의 구분, 작은 화면에서의 정체성

- **O:** 촬영일 select의 option label에는 revision이 없고 전체 식별은 title/상세에 있음.
  모바일 구역/날짜 정밀도 문장이 잘림(K2, 관련 SiteExploreCanvas/Shell).
- **H/영향:** 같은 날짜의 여러 보정본을 실제로 접했을 때 구분이 어려울 수 있음. 현재 실제
  표본에는 그 충돌을 체험할 복수 corrective revision 사례가 없어 발생 빈도/오선택은 미검증.
- **제안:** 보정본 구분이 필요한 자리에는 짧은 제출 버전 요약을 별도 읽을 수 있는 줄로 표시.
  전체 원본·revision·digest는 상세. native option을 억지로 여러 줄로 만든다는 가정은 하지 않음.
- **trade-off:** 모든 날짜 option에 파일명/digest를 추가하면 선택이 어려워짐. 공통 시점 정보는
  짧게, 충돌/선택 버전의 식별 정보는 문맥적으로 보강. 원래 결과의 exact selector는 바꾸지 않음.
- **검증:** 같은 관측의 보정본이 있는 테스트 자료에서 구분, 원래 결과 재열기, 새 비교 생성
  의도 구별. 실제 데이터/계약을 이번 조사에서 추가·변경하지 않음.

### F6 · P2 — 결과 요약에서 근거/검토로 갈 때 설명 수준이 급변

- **O:** 요약에는 날짜·값·한계가 함께 있어 개선됨. 검토 상세의 캡처는 긴 ref/digest 중심으로
  밀도가 높음. 실제 링크와 저장 검토는 정상 연결됨(K1/K6).
- **H/영향:** 숫자를 확인하는 사람과 근거를 확인하는 사람의 이해가 끊길 수 있음. 공식 승인
  오해나 무단 공유가 실제로 발생했다는 증거는 없음.
- **제안:** 같은 결과 ID/구역/원래 입력·합성 여부·용도 제한을 상세에서도 사람용 요약으로
  먼저 유지하고, 기술 ref는 계속 발견 가능하게 둠. 검토는 공식 승인과 구별.
- **trade-off:** 자료를 볼 수 없는 결과/권한에서는 지도 대신 정직한 입력 요약을 제공.
  수치를 실제 해안 사진에 붙이거나 결과 overlay를 새로 만들어 이 문제를 해결하지 않음.
- **검증:** 이용자가 ‘어떤 두 입력의 어떤 구역 결과이며 무엇을 보증하지 않는지’를 설명하고,
  해당 근거와 저장 검토를 찾는지 확인. 출력·공유는 지원 계약/권한 안에서만 별도 검사.

## 6. 유지할 강점과 채택하지 않은 주장

유지: 실제 guarded 픽셀 첫 화면, 촬영 정밀도 정직성, 날짜/레이어 URL 맥락, 부분 DSM 표시,
정량 차단과 독립 열람의 구분, 별도 합성 수치 사례, 결과와 제한의 동시 표기,
실제 결과→근거·검토 경로, 권한별 설명과 keyboard disclosure.

독립 검토의 제안도 그대로 수용하지 않았다. 경쟁사가 정확도를 ‘속인다’는 근거는 없으며,
‘같은 날짜 option’만으로 기존 분석 입력이 실제로 바뀌었다는 증거도 없다.
누가 표시 작업을 만들었는지 보여주는 안은 존재/계정 정보 노출 위험이 있어 채택하지 않는다.
없는 drag 기능의 hint, 비교 slide/열지도/3D, 새 export 기능을 ‘익숙한 UX’라는 이유로 추가하지 않는다.

## 7. 구조 대안: 기능 추가보다 작업공간의 관계를 바꾼다

| 안 | 장점 | 비용/위험 | 판단 |
|---|---|---|---|
| A. 현재 페이지 구성 유지, 메뉴/중간 진입/도구 위치만 정리 | 기존 경로와 시각 정체성 보존, 회귀 범위 작음 | 공간 작업과 자료/근거 페이지 이동이 계속 분절 | 비교 baseline으로 유지 |
| B. 현장 안의 공간 작업면 + 필요 시 하나의 패널 | 날짜/레이어/선택/결과 맥락을 가까이 유지, 지도 조작 위치 일관 | 패널 열림/복귀·권한/정확한 source 상태 관리 필요 | **우선 검증할 가설** |
| C. 좌·우 패널을 항상 펼친 3단 편집기 | 정보 동시 비교 | 1440에서도 canvas 축소, 모바일 불가, 첫 사용자 판단 과다 | 기본안으로 채택하지 않음 |

B의 정보구조 가설: 전역 현장/작업 이동은 유지 → 현장/WorkArea/관측·선택 버전의 orientation →
공간 작업면에서 탐색/가능한 비교/기록 결과 → 관측·레이어 또는 선택 결과의 상세를 필요 시 패널로 열기.
자료 등록·준비·관리는 지원 동선이며 삭제하지 않는다. 동일 정보를 좌측과 우측에 동시에 복제하지 않는다.
모바일은 데스크톱 3열을 축소하지 않고 한 작업면 + 닫을 수 있는 목록/상세로 비교할 수 있다.

이는 **구조 검증 후보**이지 새 visual authority가 아니다. 기존 모노톤·타입·컴포넌트와
현장 책임을 보존하며, 다른 제품의 브랜드/색상/아이콘/자산을 복제하지 않는다.

## 8. 다음 설계 검증과 실제 사용자 조사 프로토콜

### 구현 전에 확인할 것

1. F1–F3을 우선순위로 A/B의 과업 구조를 비교한다. 임의 고충실도 별도 데모를 납품물로 삼지 않는다.

3. 구조가 채택되면 실제 Console에 반영하고 같은 T1–T9를 반복한다. 기술 tests·render·입력 방법
   검증은 서로 별개로 남긴다. 정량 조건/계정 데이터가 없는 상태는 unavailable로 보고한다.

### 사람을 대상으로 검증할 질문 — 아직 실행하지 않음

- 1차는 소규모 **정성 조사 제안**: 운영/디지털 담당, 검토 담당, 모바일 읽기 사용자를 포함한
  5–8명 정도. 역할과 공간도구 경험을 기록하고 분석을 구분한다. 통계적 대표성 주장은 하지 않는다.
- 시나리오: 지정 현장/촬영일 찾기, DSM 변경 후 돌아오기, 부분 보기 설명, 비교가 안 되는 이유,
  800m³의 입력과 제한 설명, 저장 검토 찾기, 같은 관측의 보정본/원래 결과 구별.
- 과업 문구에 메뉴 이름을 알려주지 않는다. 첫 클릭, 완료/실패/도움, 잘못된 메뉴 진입과 복귀,
  이해한 입력/제한, task time과 대기 시간을 따로 기록한다. think-aloud 부담도 표기한다.
- A/B를 비교하면 순서 효과를 줄이고 같은 조건·자료로 수행한다. 한 사용자의 두 화면 경험을
  독립 표본처럼 세거나 무근거 SUS/성공률 점수를 생성하지 않는다.
- 필수 안전 기준: 다른 입력/구역/보정본을 같은 결과로 읽는 오해를 남기지 않을 것; 합성/실제와
  열람/수치/공식 승인 구별. UI가 이를 유발하면 ‘시간은 빨라졌다’로 수용하지 않는다.
- 시간·클릭 목표는 baseline 관찰 후 설정한다. 현재 자동화에 사람의 10초/30초 성공 기준을
  끼워 넣어 결과를 유리하게 만들지 않는다. 물리 touch·키보드·SR은 각각 검사한다.

이 단계는 실제 참가자·동의·접근 가능한 자료가 필요하다. 현재는 전문가/공식 자료 기반
조사를 완료한 것이며, 미실행 사용자 연구를 완료·실패로 포장하지 않는다.

## 결론

KSI의 첫 화면은 이미 실제 자료를 보여주지만, **기능 영역을 오가는 관리형 페이지와 공간자료
조작을 중심으로 한 작업공간 사이에 구조적 간극**이 있다. 먼저 해결할 것은 F1 길 찾기,

상세의 읽기 순서를 보완한다. 새로운 3D·열지도·재구성·보고 기능 수를 늘리는 것이 결론은 아니다.
