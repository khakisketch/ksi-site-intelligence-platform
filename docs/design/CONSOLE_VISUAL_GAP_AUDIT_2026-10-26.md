## 1. 시스템 전반의 시각적 결함

### S-01. 작은 회색 텍스트가 화면을 지배한다 — High

- 크기 20종(10, 10.5, 11, 11.5, 12, 12.5, 13, 13.5, 14, 14.5, 15, 16, 17, 18, 19, 20, 22,
  24, 26 등)이 혼용된다. 사용 빈도는 `12px` 470회, `12.5px` 203회, `13px` 184회,
  `11.5px` 166회, `11px` 67회다. 26px는 2회뿐이다.
- 결과적으로 제목 한 줄 뒤에 11.5~13px 설명·메타데이터·상태 문장이 이어진다. 작업공간
  우측 패널, 분석 요약, 작업 상세가 대표적이다.
- 증거: `workspace-1440.png` 우측 `작업공간 정보`, `results-1440.png` 좌측 요약,
  `work-order-1440.png` 중단 `관측 자료 등록`.
- 권고: 5단계 타입 스케일(예: 26/20/15/13/11.5)로 축소하고, 카드 안에서는 2단계 이하만
  쓴다. 본문 13px, 보조 11.5px, 제목 15/20/26px.

### S-02. 화면 아래 절반이 비어 있다 — High

- 현장 목록: 카드 2장 아래 약 45% 공백. 홈: 안건 1장과 우측 목록 아래 약 55% 공백.
  외부 비교 기록: 카드 1장 뒤 약 65%. 구역 자료 준비: 선택 상자 뒤 약 70%.
  계정: 사용자 카드 뒤 약 65%. 도움말·지원 범위·로그인도 같은 문제.
- 증거: `home-1440.png`, `sites-1440.png`, `observations-1440.png`, `requests-1440.png`,
  `account-1440.png`, `help-1440.png`, `support-1440.png`, `login-1440.png`.
- 원인: 콘텐츠가 적을 때 채울 구조(요약 레일, 최근 활동, 범례, 안내 타일)가 없고,
  `max-width`만 넓게 두고 카드 폭은 좁게 둔다.
- 권고: 빈 공간을 장식으로 채우지 말고, 실제로 존재하는 요약(현장 수, 최근 갱신,
  작업구역 수, 최근 관측일)을 같은 그리드에 배치한다. 정보가 정말 없으면 페이지 폭을
  줄여 “비어 있음”이 의도된 여백으로 읽히게 한다.
- 보조 지표(픽셀 분포, 품질 점수 아님): 본문 영역에서 페이지 배경색이 차지하는 비율은
  홈 81.5%, 현장 78.8%, 받은 업무 71.1%, 팀 91.4%, 계정 93.5%, 도움말 97.8%,
  외부 비교 기록 87.1%, 구역 자료 준비 81.5%, 신규 관측 89.3%다. 반대로 결과 59.9%,
  작업 상세 58.2%는 흰 카드가 화면을 덮어 **빈 화면이 아니라 텍스트 벽**이다.
  두 문제를 같은 ‘여백 부족’으로 뭉뚱그리지 않는다.

### S-03. 같은 ‘없음’이 화면마다 완전히 다른 모습이다 — High

- 큰 점격자 패널(작업공간·자료·비교, 약 850×280px), 검은 빈 사각형(Sample Field 작업공간,
  약 850×280px), 작은 아이콘+한 줄(현장 카드), 중앙 아이콘+문장(받은 업무),
  아무 표시 없는 권한 거부(팀·현장 등록)가 공존한다.
- 증거: `workspace-1440.png`, `workspace-2-1440.png`, `materials-1440.png`,
  `compare-1440.png`, `inbox-1440.png`, `team-1440.png`, `sites-1440.png`.
- 특히 Sample Field의 **거대한 검은 사각형**은 “자료가 없다”보다 “화면이 고장 났다”로 읽힌다.
- 권고: `없음`을 하나의 상태 컴포넌트로 통일하되, ① 보관 만료 ② 준비 전 ③ 권한 없음
  ④ 확인 불가 ⑤ 실제 0건을 **아이콘+라벨+한 줄 사유+복구 행동**으로 구분한다. 기본 높이는

### S-04. 실제 데이터가 시각화되지 않는다 — High

- 관측 시점, 작업구역 범위, 작업 상태, 분석 차단 사유가 모두 문장과 배지로만 표현된다.
  타임라인·진행 단계·범위 미리보기·결과 요약 그래픽이 없다.
- 현장 카드에는 실제 작업구역 경계가 있음에도 시각 정보가 `미리보기 없음` 한 줄뿐이다.
  작업구역 화면에만 컬러 지도가 있고, 다른 화면은 전부 텍스트다.
- 증거: `sites-1440.png`, `workspace-1440.png`(관측 시점 select), `work-order-1440.png`
  (진행 상태가 문장), `results-1440.png`(차단 상태가 문장), `observations-1440.png`.
- 권고: ① 관측 시점 수평 레일(실제 촬영일·정밀도) ② 작업 단계 stepper(등록→검사→준비→
  분석→검토) ③ 등록 범위/자료 범위의 실제 SVG 미리보기 ④ 값이 있을 때만 결과 요약
  (변화량·유효/제외 면적)을 숫자+막대로 표시. 값이 없으면 그래프를 만들지 않는다.

### S-05. 헤더가 4~5층으로 겹친다 — High

- 예: `현장 상세`(상단바) → `‹ 현장`(breadcrumb) → `Floreat public sample` → `작업공간·자료·결과`
  탭 → `현장 변화 분석`(본문 h2). 작업 상세는 `‹ 작업` → `현장 작업` → 전역 업무 탭 →
  `관측 자료와 검사 확인`.
- 증거: `results-1440.png`, `observations-1440.png`, `work-order-390.png`.
- 권고: 상단바 제목은 전역 목적지 하나만, breadcrumb은 1단계, 사이트명과 탭을 한 줄로
  묶고, 본문 h2는 실제 작업 제목만 남긴다. 최대 3층.

### S-06. 한 화면에 1차 행동이 두 개 이상이다 — High

- 작업공간: `구역 자료 준비에서 확인`(검정)과 우측 `이 구역의 최근 분석 확인`(검정)이 동시에
  보인다. 작업 상세: `등록 자료 목록 보기`(외곽선)와 `변화 분석에서 비교하기`(검정)가 나란히
  있고, 위에 `검사와 비교·정리` 배지가 또 있다.
- 증거: `workspace-1440.png`, `work-order-1440.png`, `materials-1440.png`.
- 권고: 화면당 검정 1차 행동 1개. 나머지는 외곽선/텍스트 링크로 강등하고, 행동이 다른
  목적지면 섹션으로 분리한다.

### S-07. 우측 정보 패널이 ‘작은 카드의 긴 목록’이다 — High

- 1280px에서 본문을 약 720px로 줄이면서, 우측은 300px 안에 8~10개의 작은 카드와 11.5px
  텍스트를 쌓는다. 접힘도 많아 탐색 비용이 크다.
- 증거: `workspace-1280.png`, `materials-1280.png`, `compare-1440.png`.
- 권고: `요약 / 자료 / 검증` 탭 또는 3개 섹션으로 재편하고, 핵심 3개 값은 크게, 나머지는
  펼침으로. 1280 미만에서는 드로어로 내리되 열었을 때 폭을 360px 이상 확보한다.

### S-08. 표면·깊이·색의 시스템이 빈약하다 — Medium

- 흰 카드/아주 옅은 회색 배경/1px 테두리만 반복되고, 그림자 클래스는 앱 전체에서 12회
  등장하며 그중 일부는 `shadow-none`이다. 라운드는 8종(full/lg/md/xl/4px/10px/1px/tl)이
  역할 구분 없이 섞인다. 화면이 “종이 위에 선을 그린” 느낌으로 평평하다.
- 증거: `home-1440.png`, `sites-1440.png`, `help-1440.png`, `account-1440.png`.
- 권고: 카드 radius 8px, 입력 6px, 배지 full로 제한. 깊이는 sticky/drawer/modal에만
  사용하고, 일반 카드는 테두리와 배경 대비로 구분한다. 그림자를 늘리기보다 **면의 대비와
  간격**으로 위계를 만든다.

### S-09. 컬러 지도만 혼자 튄다 — Medium

- 증거: `work-areas-1440.png` vs `workspace-1440.png`.
- 권고: 지도 타일을 저채도/라이트 그레이로 조정하고(제공자·타일 정책 변경은 별도 승인),
  작업구역 폴리곤·현장 범위를 강조색으로. 동일한 “지도 언어”를 현장 카드·요청·작업공간에
  재사용한다. 외부 타일 의존을 늘리지 않는다.

- 증거: `materials-1440.png`, `work-order-1440.png`, `sites-1440.png`.
- 권고: 16/20px 단일 스트로크 아이콘 세트와 파일 유형 아이콘을 도입한다. 아이콘은 장식이
  아니라 스캔 속도를 위한 것이다. 색만으로 구분하지 않는다.

### S-11. 상태 배지가 우선순위를 시각화하지 않는다 — Medium

  알약이다. 위험/대기/완료의 무게가 같고, `차단됨`만 빨간 테두리로 튄다.
- 증거: `work-1440.png`, `results-1440.png`, `work-order-1440.png`.
- 권고: 상태를 ① 사람이 결정해야 함 ② 진행 중 ③ 막힘 ④ 완료로 묶고, 각각 아이콘·채움
  강도·정렬 순서를 다르게. 색은 안전 상태에만 쓰고, 나머지는 무게와 위치로 구분한다.

### S-12. 모바일에서 제어가 잘리거나 떠 보인다 — High

- 업무 상태 필터가 `운영 상태 확인 필…`로 잘린 채 가로 스크롤된다. 스크롤 가능 표시가 없다.

  `Floreat co…`로 잘린다. 비교 화면은 `목록·작업구역·두 시점 비교·정보`가 여러 줄로 흩어진다.
- 증거: `work-390.png`, `materials-390.png`, `compare-390.png`, `workspace-390.png`.
- 권고: 모바일 필터는 2줄 또는 “필터” 시트로. 상단 도구는 한 줄에 1차 행동만. 잘린 이름은
  탭하면 전체가 보이는 경로를 명시한다. 비교 모드는 상단 컨트롤을 고정하지 말고 접는다.

### S-13. 목록·표의 스캔 리듬이 약하다 — Medium

- 업무 표는 열 정렬은 좋지만 12px 텍스트와 얇은 구분선만으로 행이 구분된다. 날짜·담당·
  기한이 모두 같은 회색 무게다. 현장 목록의 두 카드는 서로 구분되는 시각적 정체성이 없다.

## 4. 썸네일 문제의 정확한 상태

- 이전의 풍경형 기본 표지는 합성 사진처럼 읽힐 수 있어 제거됐다(INV-040/ADR-025 D3).
- 실제 픽셀이 있으면 `SitePreviewThumb`가 실제 미리보기를 그린다. 지금은 만료로 없다.
- 실제 범위를 그리는 `SiteVisualTile`(등록 WorkArea 링 + 래스터 범위)은 코드에 남아 있으나
  2026-10-23 `99ca16fc`에서 카드에서 제거됐다. 현재는 어디에서도 사용되지 않는다.
- **권고:** 풍경 그림을 되살리지 말고, 이 실제 범위 타일을 “현장 지문”으로 단순화해
  카드·홈·신규 관측 목록에 쓴다. 캡션은 `범위 도식 · 사진 아님` 한 줄이면 충분하다.
  범위가 없으면 이니셜+상태의 조용한 타일을 쓰고, 절대 사진처럼 보이게 하지 않는다.

## 5. 권장 시각 방향 — “Field Atlas”

1. **현장 정체성**: 실제 범위 폴리곤/자료 footprint를 얇은 선의 지도 조각으로. 사진이 없어도
   현장마다 다른 실루엣을 갖는다. 색은 무채색+한 가지 강조(현재 잉크 블랙).
2. **시간 축**: 관측 시점을 카드·작업공간·결과에 같은 수평 레일로. 날짜 정밀도(`날짜만 확인`)는
   레일 위 라벨로 유지한다.
3. **작업 단계**: 작업 상세에 `등록 → 검사 → 준비 → 분석 → 검토` stepper. 현재 상태와 막힌
   지점을 한눈에. 단계는 실제 상태에서만 파생한다.
4. **결과 시각화**: 값이 있을 때만 숫자+단위+막대/범위. 없으면 “산출물 없음”과 필요한 입력을
   보여주고 그래프를 만들지 않는다.
5. **없음의 언어**: 한 컴포넌트, 5가지 사유, 160~200px, 아이콘+제목+한 줄+복구 행동.
6. **타이포/표면**: 5단계 타입, 8px 카드 radius, 그림자는 overlay에만. 색은 안전 상태만.
7. **지도**: 저채도 지도 + 강조 폴리곤. 지도 높이를 줄이고 옆에 범례·범위 수치를 둔다.
8. **헤더/행동**: 3층 이하, 검정 1차 행동 1개, 나머지는 조용한 링크.
9. **모바일**: 필터는 시트, 도구는 한 줄, 카드는 1열. 비교 모드는 상단 고정을 해제.

| P3 | 로딩 skeleton·오류·hover/focus·모션 | 상태 완성도 |

## 6.1 실행 순서 제약

- P0-3(작업공간/자료/비교 무대)은 현재 **다른 작업 단위가 수정 중인**
  `SiteWorkspaceShell`, `SiteMosaicViewport`, `SiteWorkspaceResults`, `spatial-assets`와
  겹친다. 그 변경이 통합·검증되기 전에는 같은 파일을 동시에 고치지 않는다.
- P0-1(현장 지문), P0-2(없음 상태), P0-4(시점 레일·단계 stepper)의 공통 컴포넌트와
  홈·현장·업무 적용은 보호 파일과 분리해 먼저 진행할 수 있다.
- 실제 픽셀이 복구되면 카드·무대의 시각 품질을 다시 검증한다. 만료 상태만 보고
  “사진이 있을 때의 완성도”를 판정하지 않는다.

## 7. 지켜야 할 경계

- 합성 사진·가짜 위성영상·placeholder를 실제 관측처럼 보이게 하지 않는다(INV-040/ADR-025 D3).
- 만료·권한·미확인을 숨기거나 0으로 바꾸지 않는다.
- 범위 도식은 좌표·범위를 실제 값에서만 그리고, “사진 아님”을 유지한다.
- 시각화가 정확도·정량 사용 가능·현장 수용을 암시하지 않는다(INV-051/053).
- 외부 지도 제공자·타일 정책·데이터 반출 변경은 별도 승인.
- P0는 UI·표현 계층이며 Core 계약·권한·저장·계산을 바꾸지 않는다.

## 8. 미확인

- 실제 픽셀이 살아 있는 ready 상태의 시각 품질(현재 만료).
- 팀 목록 populated, 분석 결과 값이 있는 상태, 외부 기록 populated.
- 물리 터치·스크린리더·고대비·인쇄.
- hover/focus/loading/error 상태의 전체 렌더(초기 캡처만 확인).
- 사용자 첫 클릭·tree test·현장 담당자 인터뷰.
