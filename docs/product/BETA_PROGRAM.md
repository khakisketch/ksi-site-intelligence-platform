# KSI 공개 베타 프로그램 (적합성 판정 + UX 피드백 병행)

Status: 2026-10-20 Human 승인 범위. **제품 정의를 다시 만들지 않는다.** 이 문서는 확정된
장기 계약([`PRODUCT_CONSTITUTION.md`](PRODUCT_CONSTITUTION.md) §제품 정체성)과
[ADR-KSI-038](../architecture/ADR-KSI-038-spatial-data-and-analysis-platform.md),
[ADR-KSI-039](../architecture/ADR-KSI-039-physical-site-intelligence-and-acquisition-separation.md)
아래에서 **참가자에게 무엇을 약속하고 무엇을 약속하지 않는지**, 그 약속을 측정하고 개선하는
방법만 정한다. 제품 계약·판정 의미·권한·보관/반출 규칙은 바꾸지 않는다.

## 1. 왜 지금 베타인가

지금까지의 증거는 전부 **로컬 소프트웨어 증거**다. P-AC-01(외부 개발자의 독립 사용)과
P-AC-06(운영·고객 수용)은 로컬로는 닫히지 않는다. 제품 책임자가 현장에 가지 못하더라도,
참가자가 자기 업무·자기 데이터로 수행하는 과정에서 생기는 마찰은 직접 관측 가능하다. 베타는
그 신호를 얻는 경로이며, 제품 책임의 대리 acceptance가 아니다.

## 2. 베타가 약속하는 것 / 약속하지 않는 것

| | 내용 |
|---|---|
| **약속** | 참가자가 제출한 산출물이 **어떤 용도로 쓸 수 있는지, 왜 안 되는지, 무엇을 고치면 되는지**를 근거와 함께 정확히 알려준다. 조건이 충족되면 계산 결과까지 제공한다. |
| **약속하지 않음** | 수치 결과의 즉시 제공, 정확도·측량·정산의 보증, 벤더·도구 호환성, 현장 수용성, 수집·재구성 수행(참가자 산출물은 참가자가 만든다 — ADR-KSI-036 D6). |
| **판정 층 유지** | 자료 유효성 / 목적별 사용 적합성 / 분석 결과 재현 가능성. 열람 가능하다고 정량 사용 가능을 뜻하지 않는다. |
| **결과 보존** | 계산 결과·근거는 불변·가산 기록이다. 정량 활용이 차단되어도 감사·재현용 역사 기록은 삭제·봉쇄하지 않는다. |

참가자 데이터는 격리 보관하고 **베타 종료 시 폐기**할 수 있어야 한다(보관 기간·삭제 시점은
§6의 제품 결정 대기 항목). 참가자가 제공한 산출물의 사용권·보관 동의는 등록 단계에서 명시
적으로 받는다.

## 3. 참가자 동선 (2026-10-20 실리그에서 검증)

1. 로그인 (OIDC) → 2. 현장 등록 3단계(기본정보 → 범위·좌표계 → 확인·등록) → 3. 작업구역 →
4. 관측 자료 등록(참가자 산출물 제출) → 5. 적합성 판정과 근거 확인 → 6. 비교 가능 시 분석
요청과 결과·근거 → 7. 사람 검토 → 8. 다음 관측 연결.

사용자 관점에서 가장 중요한 지점 하나: **4~6번에서 참가자가 처음 마주치는 것은 수치가 아니라
판정과 그 근거**다. 판정이 정직하고 보완 경로가 명확해야 베타의 가치가 생긴다. 이 구간의
안내 문구는 이미 typed blocker마다 사유·담당·다음 단계로 정리되어 있고
(`apps/dashboard/src/lib/analysis-guidance.ts`), 참가자 관점에서 고쳐야 할 지점은 §5-G3
(담당자가 참가자 본인에게 향함)에 기록되어 있다.

## 4. 준비 상태 — 검증된 사실

증거: 스크래치 리그(포트 8093). F-03 리그 데이터·권위 디렉터리를 **사본**으로 띄우고, 사본의
OIDC subject registry만 v2로 전환해 `SITE_BOOTSTRAP` capability를 부여했다. **라이브 F-03
리그(8092)와 데이터·digest·계측값은 건드리지 않았다.** 참가자 계정으로 신규 현장 등록부터
실제 화면을 조작해 확인했다.

| ID | 분류 | 내용 |
|---|---|---|
| G1 | **외부 입력** | OIDC subject registry가 v1이라 `capabilities`가 없고, 그 결과 **어떤 계정도自行 현장 등록을 못 한다**(화면: "현장 등록 권한이 없습니다"). registry를 v2로 전환하고 `capabilities: ["SITE_BOOTSTRAP"]`를 주면 해결된다. **제품 코드 변경 없음.** 파일 교체 + Core 재시작이 반영 시점이다. |
| G2 | **지금 가능** | 현장 등록 2단계에서 **현장 좌표계와 높이 기준을 직접 입력해야** 하며, 비어 있으면 "다음"이 **이유 설명 없이 비활성**된다. 참가자는 무엇이 비었는지 알 수 없다. |
| G3 | **지금 가능** | 판정 안내 문구가 "담당자가 확인하세요"로 끝난다. 베타 참가자는 **산출물 제공자 본인**이라 담당자가 없다. 보완 경로가 참가자가 직접 실행할 수 있는 문장으로 정리되어야 한다. |
| G4 | **제품 결정** | 현장 등록 2단계의 경계 그리기는 **공개 OpenStreetMap 타일** 위에서 이뤄진다(관측: `tile.openstreetmap.org` 요청 6건). 참가자의 현장 위치가 타일 제공자에게 그대로 노출된다. Console의 "외부 클라우드 처리 / 반출 허용" 동의는 **이 제3자 반출을 덮지 않는다.** 베타 약관에 명시하거나 타일 제공자·자체 호스팅을 고쳐야 한다. |
| G5 | **지금 가능(수정 완료)** | 참가자가 경계를 직접 그렸는데도 현장 카드가 "경계 미설정"이라 했다. Core 원장에는 AOI 3개 꼭짓점이 **저장돼 있었다**. 상태 표기가 사실과 어긋나 participant 데이터에 대해 거짓말을 한다 → `UNMAPPED` 표시를 "관측 시작 전"으로 고쳤다(`labels.ts`, `site-progress.ts`). |
| G6 | **제품 결정** | 현장 상태 어휘와 진행 막대는 **취득(acquisition) 수명주기**다(초기 매핑 → 모델 처리 → 모델 검증 → 임시 자율운영 → 순찰 준비 → 순찰 중). 현 제품(자료+분석)은 이 수명주기를 진행하지 않는다(ADR-KSI-039). 참가자는 1단계에 영구히 머문다. 참가자에게 이 어휘를 그대로 보여줄지 결정이 필요하다. |
| G7 | **외부 입력** | 공개 배포의 운영 입력이 남아 있다: 공개 VM·도메인·DNS, **OIDC만 허용하는** 사람 로그인(외부 VM), 보호된 subject registry, secret 파일, 원장/객체 저장소와 백업 복원. 템플릿과 준비 절차는 이미 문서화돼 있다([`docs/ops/VM_DEPLOYMENT_READINESS.md`](../ops/VM_DEPLOYMENT_READINESS.md), [`docs/ops/DEPLOYMENT.md`](../ops/DEPLOYMENT.md), [`docs/ops/RELEASE_EVIDENCE.md`](../ops/RELEASE_EVIDENCE.md)). |

## 4-1. 2026-10-20 실제 서비스로 띄워 본 결과

합성 스테이징 스택(`deploy/compose.synthetic-staging.yaml`)을 **현재 소스로 다시
만들어** 실제 서비스 형태(Docker 컨테이너 · Tailnet HTTPS · 컨테이너 안의 OIDC
로그인 · MinIO 객체 저장소 · presigned 업로드)로 띄우고, 참가자 계정으로 화면을
직접 조작했다. 확인된 것:

- 로그인 왕복 성공 (컨테이너 안의 NextAuth ↔ OIDC issuer ↔ Core whoami).
- 신규 현장 등록 성공 (SITE_BOOTSTRAP capability), 작업구역 등록 성공(경계 폴리곤),
  관측 작업 생성 성공.
- 실제 파일 업로드 성공 — 427 바이트 정사영상이 presigned URL 로 MinIO에 들어갔고
  등록 화면이 "파일 전송 완료"를Showing했다.
- 제출 직후 상태는 정직했다: "이 봉인 파일에 적용할 검사 기준이 아직 준비되지
  않았습니다" — 검증 완료를 뜻하지 않는다고 명시했다.

**이 스택에 없는 것(중요)**: 독립 외부 검사/측정 워커와 그 보호된 활성화 설정이다.
그래서 참가자가 낸 파일은 이 환경에서 검사·판정까지 진행되지 않는다. 정량 판정을
끝까지 보여주려면 워커를 이 조합에 붙여야 하고, 그게 다음 작업이다.

### 9. 스택을 못 다시 만들게 했던 두 가지 (수정 완료)

| ID | 분류 | 내용 |
|---|---|---|
| G8 | **지금 가능(수정)** | OIDC 모드 Core 는 `KSI_CORE_OIDC_SUBJECT_REGISTRY_FILE` 없이는 기동하지 않는다(기본값으로 넘어가지 않는다). 그런데 합성 스테이징 템플릿은 그 env를 넘기지 않아 **12일째 떠 있던 스택이 현재 코드로 재기동되지 않았다.** `prepare_state.py`가 issuer 의 개발 계정 목록을 읽어 v2 subject registry 를 생성하고, compose 가 그것을 Core 에 붙이도록 고쳤다. 계정 목록은 두 곳에 적지 않는다 — issuer 모듈에서 읽는다(계정이 어긋나면 로그인 자체가 401). |
| G9 | **지금 가능(수정)** | 컨테이너 → OIDC issuer 도달성: issuer 는 loopback 전용이고 tailscale serve 가 tailnet 인터페이스에서만 TLS 를 끝내므로 브리지 네트워크 컨테이너는 public URL 로 닿지 못했다(컨테이너 안 로그인이 `fetch failed`). 고정 서브넷 + 게이트웨이 TLS 브리지(`deploy/bin/issuer-tls-bridge.py`) + `extra_hosts` 로 컨테이너와 브라우저가 같은 issuer URL·같은 token issuer 를 보게 했다. |


## 5. 측정 계획

로드맵이 이미 정한 성과 지표를 그대로 쓴다(목표 수치는 참가자가 생긴 뒤 정하고 지금은 약속하지
않는다).

| 지표 | 측정 방법 |
|---|---|
| 최초 유용 결과까지 시간 | 참가자 세션 시작 → 첫 판정(또는 첫 결과) 도달. Core의 라우트 로그 correlationId와 참가자 기록을 대조. |
| 반복 준비 시간 | 두 번째 관측 등록·요청까지 걸린 시간(첫 회차를 기준으로). |
| 지원 개입 횟수 | 운영자가 개입한 횟수(질문 응답·수동 처리). |
| 재사용 여부 | 같은 구역/설정으로 두 번째 주기를 시도했는가. |
| 저장·연산·전송량/비용 | 참가자 1인당. |

판정 품질 측정은 참가자가 제출한 산출물별로 **어떤 용도로 쓸 수 있었는지/없었는지**를 기록한다.
수치 결과가 없으면 그것은 실패가 아니라 **판정 결과**로 기록한다.

## 6. 제품 책임자가 정해야 하는 것 (운영자가 판단으로 완화하지 않음)

1. **보관·삭제 정책**: 베타 기간 중 제출 산출물의 보관 기간, 삭제 시점, 삭제 증빙.
2. **제3자 지도 반출**(G4): 공개 타일을 그대로 쓸지, 자체 호스팅 타일을 쓸지, 약관에 명시할지.
3. **참가자 범위**: 몇 명, 어떤 역할(FIELD_OPERATOR/ADMIN), 어느 조직.
4. **현장 상태 어휘**(G6): 획득 수명주기를 현 제품 화면에 남길지, 대체할지.
5. **수직 근거 정책**(별건): 참가자 산출물이 실제 수치를 얻으려면 허용 CRS·수직 근거 정책이
   정해져야 한다. 미정인 상태에서 정책 판단으로 완화하지 않는다.

## 7. 이번 베타가 증명하지 않는 것

- 현장 정확도, 측량·정산 적합성, 벤더·도구 호환성, 규제 대응.
- 참가자 산출물이 실제로 정량에 사용 가능한 비율(측정된 판정 결과로만 말한다).
- 사업 검증(지불 의사·가격·지원 비용). 기술 수용과 별도 트랙이다.
- 수집·재구성: 참가자가 만든 산출물만 등록한다(KSI가 대신 재구성하지 않는다).

## 8. 변경 이력

- 2026-10-20: Human 승인("적합성 판정 + UX 피드백 병행"). 실리그 참가자 드라이브로 G1~G7
  확인. G5(거짓 상태 표시) 수정, G6·G4·보관 정책은 결정 대기.
